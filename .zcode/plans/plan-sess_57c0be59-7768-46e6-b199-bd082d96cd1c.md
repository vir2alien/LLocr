# Функция «Разметить страницу» (layout-роль, двухфазные модели)

## Цель

Ручная команда разметки: страница (или все страницы книги) отправляется на layout-модель (TeleOCR), ответ разбирается в **блоки без текста** (тип + рамка). Дальше текст каждого блока добывается существующим ручным механизмом blockRecognition («Распознать» в BlockEditPanel). В автоматический пайплайн (decision/autoRecheck) ничего не встраиваем — только ручные действия.

## Принятые решения

1. **Модель разметки = модель blockRecognition** (настройки «Модель blockRecognition», `check/*`). У TeleOCR разметка и распознавание блоков — одна модель, разница только в промпте. Роль `layout` добавляется в профиль модели (промпт, парсер, параметры); если у активной blockRecognition-модели layout-роли нет — кнопка «Разметить» неактивна. Отдельное окно настроек «Модель layout» позже, при необходимости.
2. **Content из ответа разметки игнорируется** — блоки создаются пустыми.
3. «Разметить» **заменяет** блоки страницы; если уже есть блоки/текст — диалог подтверждения.

## Шаг 1. Формат ответа TeleOCR

Формат не задокументирован (карточка HF показывает только ContentBlock). Промпты подтверждены карточкой: «Analyze the image layout.» и «Multi-point Layout Segmentation Analysis.». Парсер делаю толерантным к вариантам (wrapped `<|ref|>…<|/ref|><|det|>[[x1,y1,x2,y2]]…<|/det|>` / голый `label [x1,y1,x2,y2]` / angle); реальный ответ зафиксируем в docs/15-teleocr.md при первом прогоне.

## Шаг 2. `resources/profiles/models/teleocr.json`

Роль `"layout"`: `parser: "teleocr-layout"`, `maxOutput: 4096`, два промпта, `request` как у ocr-роли, `launch` пустой. В `blocks.styles` ocr-роли: `figure→image`, `formula→equation`, list/code/seal/header/footer/abstract/reference → осмысленные стили. `BoxListModel::isImageBox` считает `figure` image-блоком.

## Шаг 3. Парсер `teleocr-layout`

`src/parsers/TeleOcrLayoutParser` (наследник `DetTokenParserBase`, ADR 112): толерантный regex, нормализация координат через `ParserOptions::bboxRange`; регистрация в `ParserFactory`.

## Шаг 4. Ролевая инфраструктура

`RequestProfileStore`: роль `Layout` (`roleName` "layout", `userFileName` requestLayout.json), built-in из layout-роли, активный id = активная blockRecognition-модель. `SettingsStore`: ключ `layout/requestProfileId`. Подключение — `ensureConnectionReady(ConnectionRole::BlockRecognition)`, `ConnectionRole`/`RuntimeController` не трогаем.

## Шаг 5. LayoutModel + LayoutController

`src/models/LayoutModel` (по образцу `GeneralPurposeModel`): system + user `[image, layout-промпт]`, параметры из layout-роли, ответ → `QList<BoundingBox>`. `src/app/LayoutController` (по образцу `CheckController`): текущая страница / все страницы (очередь со Stop), busy в `Controller.busy`.

## Шаг 6. AppController

`applyLayout(pageIndex, boxes)`: замена блоков, `recognized=true`, пустой текст, `editStore.reset`, `cropRevision++`, обновление моделей; `layoutAvailable` = у активной blockRecognition-модели есть layout-роль.

## Шаг 7. UI

Header.qml: «Разметить» + ▾ «Разметить все страницы»; диалог подтверждения замены; в ▾ «Recognize» — «Распознать все блоки страницы» (новый `recheckPageBlocks`: NotChecked-блоки без текста, кроме image → `startRecheckQueue`). i18n в `llocr_ru.ts`.

## Шаг 8. Тесты

Парсер (варианты формата), `test_model_preset_catalog` (роли teleocr + layout), loopback-тест LayoutController (по образцу `test_decision_model`), `test_project_store` (блоки без текста переживают save/open).
