# «Модель разметки» — четвёртая полноценная роль с окном настроек

## Цель

Роль `layout` получает собственную конфигурацию модели: группу настроек `layout/*`, `ConnectionRole::Layout`, отдельное окно **«Модель разметки»** (вкладки Model / Launch / Request, как у decision) с пунктом в меню Settings. В мастер настройки НЕ добавляется. Это осознанный пересмотр части ADR 149 («no fourth settings window») — фиксируется новым ADR.

## Принятые решения

1. **Без скрытого fallback на check-модель.** Если модель разметки не настроена: Managed → `roleConfigError` с actionable-сообщением («выберите модель в Настройки → Модель разметки»); живой сервер с совместимыми весами переиспользуется как сегодня (ADR 61). Разовая настройка в новом окне — уже скачанный TeleOCR появится в списке как установленный (файлы ищутся по repo+stem, теги ролей не участвуют), повторное скачивание не нужно.
2. Собственный профиль запроса: `layout/requestProfileId` (по умолчанию — рекомендованная модель роли, `teleocr`), пользовательские переопределения в `requestLayout.json` (механика уже есть).
3. Установленные модели с тегами других ролей в списке layout не показываются (кроме строк профилей, где состояние определяется файлами на диске) — без расширения эвристики `matchesRole`.

## 1. SettingsStore — группа `layout/*`

По образцу `decision/*`: свойства `layoutLaunchModelPath/MmprojPath/DraftPath`, `layoutRequestProfileId` (дефолт `defaultIdForRole("layout")` → «teleocr»), `layoutModelName`; ключи `layout/modelPath`, `layout/mmprojPath`, `layout/draftPath`, `layout/requestProfileId`, `layout/modelName`; записи в таблице дефолтов (guards `test_settings_store` подхватят автоматически); `resetRuntimeDefaults` + `layout/modelName`; `applyStartupMigration` — `resolveStoredModelId(kLayoutRequestProfileId, "layout")`; ветка `"layout"` в `selectModelProfile`. Роль-диспетчеры (`launchModelPathForRole`+сеттеры, mmproj, draft, `requestProfileIdForRole` — заменить текущий шим на check, `modelNameForRole`) получают ветки `"layout"`; комментарий про «layout shares the blockRecognition model» убрать.

## 2. ConnectionRole + RuntimeController

- `ResolvedConnection.h`: `ConnectionRole::Layout` + `connectionRoleName` → `"layout"`.
- `RuntimeController::roleConfigError` — ветка Layout с actionable-сообщением (сейчас проваливается в ветку BlockRecognition с чужим текстом).
- `beginRoleSwitch` — статусный тернарник: рука для Layout.
- Остальное (переиспользование/перезапуск сервера `serverRunsRole`, `roleModelPath`, `resolveExternal`, `startServer`, `estimateModelMemory`, alias) работает через диспетчеры SettingsStore без новых переключателей.

## 3. RequestProfileStore + LayoutController + AppController

- `RequestProfileStore` (Role::Layout): конструктор подписывается на `layoutRequestProfileIdChanged`; `activeProfileId()` → `layoutRequestProfileId()`.
- `LayoutController`: `ensureConnectionReady(ConnectionRole::Layout)` (сейчас BlockRecognition).
- `AppController`: `layoutRole()` и `applyLayout` берут модель из **layout**-хранилища (сейчас из check); `layoutAvailableChanged` подписан на `layoutRequestProfileIdChanged` (вместо check); текст статуса в `startLayout` переформулирован под модель разметки.

## 4. ModelInstaller + LaunchProfileStore + InstalledReconcile

- **ModelInstaller**: четвёртый `ModelQuantModel` (`"layout"`) + `Q_PROPERTY layoutQuantModels` + `layoutActiveTitle` + список пресетов `m_presetsLayout`; ветки в `quantModel` / `publishInstalled` / `reloadPresetsInternal` / `selectQuant`; републикация по `layoutLaunchModelPathChanged`; guard удаления (`removeModelRow`/`removeModel`) сравнивает и `layoutLaunchModelPath`.
- **LaunchProfileStore**: `modelIdForRole("layout")` → `layoutRequestProfileId`; `layoutModelRuntimeNote`; подписка на `layoutRequestProfileIdChanged`.
- **InstalledReconcile**: `ReconcileSelections` + `layoutModelPath` (+ точки потребления).

## 5. QML + main.cpp

- `main.cpp`: зарегистрировать singleton `RequestProfilesLayout` (инстанс уже есть), убрать устаревший комментарий.
- `Header.qml`: сигнал `openLayoutModelSettingsRequested` + пункт меню «Layout model».
- `Main.qml`: четвёртый `ModelSettingsWindow { role: "layout" }` + обработчик.
- `ModelSettingsWindow.qml`: ветка заголовка для `"layout"`; `LocationTab.qml`: активный заголовок (`layoutActiveTitle`), список профилей (`RequestProfilesLayout.profileModel`), активный id (`Settings.layoutRequestProfileId`), Connections + onActivated; `LaunchTab.qml`: `layoutModelRuntimeNote`; `RequestTab.qml`: выбор хранилища + свой текст-подсказка (параметры запроса разметки), без threshold; `ModelDownloadList.qml`: выбор списка моделей (`layoutQuantModels`).
- Визард (StepModel.qml) не трогаем.

## 6. i18n

`update_translations` + заполнить ru: заголовок окна, пункт меню, сообщение `roleConfigError`, статус переключения роли, подсказка RequestTab, переформулированное сообщение AppController.
