# Блочная модель документа (текст страницы = join блоков)

Дата: 2026-11-09. Утверждено пользователем: подход A; raw-вкладка read-only; структурные правки не из редактора v1.

## Замысел

Текст страницы сегодня — свободная строка, в которую правки блоков «сливаются» по
текстовым якорям и диффам (ADR 190 → ADR 295, очередь правок). Это породило класс
рассинхронов «блок ↔ документ»: кнопка take появляется не всегда, якоря промахиваются,
undo из нескольких источников портит текст. Устраняется моделью: **документ страницы —
всегда join канонических блоков; правка пользователя хранится в слое конкретного блока**.

## Модель

- `BoundingBox.userText` (новое поле, пусто по умолчанию) — markdown-фрагмент блока,
  отредактированный пользователем, как он должен лежать в документе (со стилевыми
  маркерами: `## `, `$$…$$`, `![alt](…)`). Непустой userText перекрывает канонический
  эффективный текст блока (`text`/`correctedText` по `useCorrectedText`).
- Текст страницы — **производимый**: `pageDocument(page)` = join по блокам в порядке
  канона, каждый блок — `userText` или канонический рендер. Вместе с ranges
  `{boxIndex, start, length}` — маппинг документ↔блок точный всегда (никаких поисков).
- «Изменено» страницы = есть хоть один непустой userText; Revert = снять все userText
  страницы. Edited-блоки помечаются (BoxCheckStatus::Edited остаётся у слоёв; для
  документаedited-информация — в userText).
- Предупреждение об AI-версии = `userText` непуст И ≠ каноническому рендеру блока —
  прямое сравнение слоёв, всегда точное и мгновенное. «Взять текст из блока» = снять
  userText (для read/fix — переключение слоя, механизмы ADR 164/259 остаются).

## Поток правки

- Push (модель → редактор): join документа + per-block `{md, canonical, hasAiVersion}`;
  DOM-блоки тегируются `data-ll-block` (уже есть).
- Pull (редактор → модель): **per-block** — мост шлёт `{blockIndex, markdown}`;
  C++ пишет `setUserBlockText`: markdown == канону → снять userText, иначе записать.
  Ввод пользователя НЕ порождает полного пуша и эха — конфликтующие писатели исчезают.
- Структурные изменения из редактора (Enter-новый блок, склейка) запрещены v1: при
  изменении числа DOM-блоков страница перепушилась каноническим join. Add/remove блоков
  — как сейчас, на канвасе.
- Undo — наш стек снапшотов карты userText страницы (Vditor-undo и его clearStack
  не участвуют; кнопки undo/redo из тулбара Vditor убираются). Чекпоинт-очистка при
  внешних изменениях (посадка блока, take, revert, смена страницы) — история не
  пересекает ветвления.

## Raw-вкладка и совместимость

- «Текст (MD)» — read-only просмотр join (копирование, tap-to-block по точным ranges,
  подсветка остаются).
- Экспорт/copyCurrentPageText — через pageDocument.
- Проект `.llocr`: userText сериализуется в боксах; pageText страницы при сохранении =
  join (совместимость). При загрузке legacy-проекта (сохранённый pageText ≠ канонический
  join) правки пользователя раскладываются в userText по ranges — разовая миграция
  поиском (последний текстовый якорь в кодовой базе).

## Удаляется

`setCurrentPageText`, `setCurrentPageTextFromEditor`, `mergePipelineChange`,
`PendingDocumentChange`/очередь, `takeSelectedBlockTextIntoDocument` (заменяется снятием
userText), `blockDocumentDiverged`-свойство (заменяется per-block сравнением),
PageEditStore-механика baseline/rebase. Соответствующие тесты переписываются.

## Не-цели v1

- Структурные правки из редактора; совместное редактирование; канбан-стиль.
- Рендер формул из userText с ошибками KaTeX (красный raw — как сейчас при мусорном OCR;
  take-версия ИИ чинит).

## Отношение к ADR

Новый ADR: «документ = join блоков, правка per-block»; supersede ADR 295 (очередь) и
остатка ADR 190 (merge). ADR 187 (утверждение) не тронут.
