# Единое окно настроек

Дата: 2026-11-10. Утверждено пользователем: 5 разделов слева; одна общая «Сохранить»/«Отмена»;
один пункт меню вместо пяти; «Сбросить все настройки» сбрасывает все разделы.

## Замысел

Сегодня настройки разложены по пяти отдельным окнам (`UiSettingsWindow`,
`OutputSettingsWindow`, `VerificationSettingsWindow`, `RuntimeSettingsWindow`,
`TaskModelsWindow`), и в меню тулбара «Настройки» — шесть пунктов, ведущих в разные
окна. Пользователь ищет настройку, а не окно: путь «Меню → Настройки → Вывод →
«Output parser»» — четыре шага до одного значения.

Сводим всё в **одно окно**: слева список разделов, справа содержимое выбранного раздела.
Разделы те же пять, что и сегодня, — контент переезжает без изменений, меняется только
рамка. Один пункт меню, одна кнопка «Сохранить», одна «Отмена» на всё окно.

Мастер настройки переезжает в подвал окна рядом со сбросом — он и раньше был отдельной
сущностью в меню, но рядом со сбросом он читается как «начать с нуля / вернуть как
было», а не как ещё один пункт меню.

## Окно

`src/qml/Settings/SettingsWindow.qml` — `ApplicationWindow`, немодальное (как остальные
вторичные окна), `background: SettingsSurface`, `footer: SettingsFooter`.

- Размер: 1040×700, минимум 880×560.
- Заголовок: «Настройки».
- Слева: `SettingsSectionNav.qml`, ширина 200 px, список из 5 пунктов (иконка +
  название). Выбранный пункт — фон `Theme.selected`. Без поиска, без фильтра, без
  группировки и вложенных деревьев.
- Справа: заголовок раздела (`Theme.subheadingSize`) и содержимое раздела в
  `ScrollView`.
- Подвал: слева `[Мастер настройки] [Сбросить все настройки]`, справа
  `[Отмена] [Сохранить]`. Кнопки сброса и мастера — `subtle` (действие не выделяется
  цветом; цвет в интерфейсе несёт состояние, а не действие — ADR 188).

### Разделы

| # | Раздел | Иконка | Содержимое | Правки |
|---|---|---|---|---|
| 1 | Интерфейс | `monitor` | `InterfaceSettings` — язык, тема | живые; Отмена откатывает по снимку |
| 2 | Вывод | `file-text` | `OutputTab` — парсер, флаги вывода, PDF-экспорт | черновик; пишется по «Сохранить» |
| 3 | Проверка | `circle-check` | `VerificationBlocksTab` — бюджет размышления, уверенность, типы блоков | живые в модель; «Сохранить» пишет файл промптов, «Отмена» откатывает |
| 4 | Runtime | `server` (новая) | `RuntimeTab` — режим подключения, таймауты, внешний/внутренний | черновик; пишется по «Сохранить» |
| 5 | Модели | `box` (новая) | таблица задач, очередь загрузки, файлы на диске | черновик; пишется по «Сохранить» |

Иконки `server.svg` и `box.svg` добавляются в `resources/icons/ui/` (каталог подхватывается
глобом `resources/icons/ui/*.svg` в `src/CMakeLists.txt` — правки CMake не требуются).

## Семантика правок

Окно работает как черновик: правки живут в виджетах, пока пользователь не нажмёт
«Сохранить». Два раздела (Интерфейс, Проверка) применяют выбор сразу — иначе смена
темы не видна до нажатия кнопки; они откатываются снимком при «Отмене» (ниже).

- **Открытие.** Каждый раздел перечитывает значения (`loadValues`), живые разделы
  снимают снимок своих «живых» изменений.
- **Сохранить.** Каждый раздел пишет черновик в настройки, затем `Settings.forceSave()`.
  Окно закрывается. Если раздел «Модели» не может сохранить (модели не установлены) —
  открывается диалог загрузки, окно остаётся открытым.
- **Отмена.** Живые разделы восстанавливают снимок, черновиковые разделы
  перечитывают значения. Окно закрывается.
- **Закрытие крестиком.** Если окно изменено — вопрос «Закрыть без сохранения?»
  (сегодня такой вопрос есть только в окне проверки).

### Живые разделы и откат

- **Интерфейс.** Язык и тема применяются сразу (пользователь видит результат выбора
  темы, не дожидаясь «Сохранить»). На открытии окна снимается снимок языка и темы;
  «Отмена» возвращает их. Прецедент — `applySnapshot` в `RuntimeSettingsWindow`
  (режим подключения, backend, релиз).
- **Проверка.** Флажки типов блоков пишутся в модель сразу (так устроен
  `VerificationBlocksModel`: модель — источник истины). На открытии снимается снимок
  вектора «тип → включён»; «Отмена» возвращает его через `setEnabled`.

## Сброс всех настроек

Кнопка «Сбросить все настройки» в подвале:

1. Спрашивает подтверждение (диалог) — сброс отменяет ввод пользователя во всех
   разделах сразу.
2. Сбрасывает все пять разделов к значениям по умолчанию **сразу** (как сегодня
   «Restore defaults» пишет в настройки, не дожидаясь «Сохранить»), и перечитывает
   виджеты разделов. Окно остаётся открытым.
3. Что именно становится умолчанием:

   | Раздел | Сброс |
   |---|---|
   | Интерфейс | язык — «системный», тема — «системная» |
   | Вывод | парсер и флаги вывода — встроенные значения; ориентация и поля PDF — по умолчанию |
   | Проверка | `Verification.resetToDefaults()` — встроенные промпты; типы блоков — по умолчанию; бюджеты размышления — 0 |
   | Runtime | режим подключения, таймауты, адрес сервера — по умолчанию |
   | Модели | выбор модели и кванта по каждой задаче — к значению роли по умолчанию (`roles.<task>.default`); профили запуска и запроса — к встроенным (`loadDefaultDraft`) |

   Модель, которой нет на диске, после сброса всё равно записывается как выбор задачи
   (так же, как при «Сохранить»), но автозагрузки не запускается — раздел покажет
   пометку «не скачана».

Что сброс **не** трогает:

- пути установленного runtime (`runtime/rootDir`) и каталог моделей
  (`runtime/modelsDir`) — иначе приложение «забыло» бы установленный runtime
  (см. баг «Models tab resets after restart»);
- ключи в OS-хранилище (ключ API, токен Hugging Face) — их чистят отдельные действия
  в разделе Runtime;
- скачанные файлы моделей на диске — сброс настроек не удаляет данные;
- служебные ключи `setupVersion` / `setupDismissed` — иначе мастер настройки всплыл бы
  сам при следующем старте.

Механика сброса — объединение уже существующих процедур: `Settings.resetToDefaults()`
(с сохранением перечисленного выше), сброс профилей запуска и запроса, сброс файла
промптов проверки, `Verification.resetToDefaults()`, сброс черновика таблицы моделей.

## Мастер настройки

Кнопка «Мастер настройки» в подвале. Мастер — модальный диалог, живущий в оверлее
главного окна, поэтому при открытии из окна настроек он перекрыл бы его. Порядок:

1. Окно настроек скрывается (`hide()`), состояние разделов сохраняется.
2. Открывается мастер (из `Main.qml`, `openSetupWizard()`).
3. После закрытия мастера окно настроек показывается снова (`show()` + `raise()`).

Пункт меню «Setup wizard» в меню тулбара убирается: мастер доступен из подвала
единого окна.

## Меню тулбара

Кнопка «Настройки» открывает единое окно напрямую — всплывающее меню из шести пунктов
исчезает. Старые пять окон удаляются вместе с их загрузчиками в `Main.qml`.

## Взаимодействие разделов

- Попап настроек задачи (шестерёнка в таблице моделей: «Launch»/«Request») остаётся
  попапом — это настройки одной задачи, а не раздел общего окна.
- Кнопка «Настроить runtime…» внутри попапа задачи (режим внешнего сервера) больше не
  открывает второе окно: она переключает список разделов единого окна на «Runtime».
  Значит `TaskModelsTable.runtimeSettingsRef` и `LaunchTab.runtimeSettingsRef` меняют
  смысл с «открыть окно» на «показать раздел».
- `TaskModelsWindow` разбирается на части: таблица задач, очередь загрузки и список
  файлов на диске переезжают в раздел «Модели» (`src/qml/Settings/ModelsSection.qml`).
