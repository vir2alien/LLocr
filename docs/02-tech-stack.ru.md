# 02. Технологический стек

> Английский оригинал: [docs/02-tech-stack.md](02-tech-stack.md)

  ## Основное приложение
  | Область        | Выбор                           | Статус | Обоснование                                          |
  | ------------- | ------------------------------- | ------ | ---------------------------------------------------- |
  | Язык          | C++                             | ✅ используется | Основной навык разработчика, производительность |
  | GUI           | Qt6 + QML                       | ✅ используется | Кроссплатформенность, удобный декларативный UI для панелей |
  | Сборка        | CMake                           | ✅ используется | Стандарт для кроссплатформенного C++ |
  | C++-пакеты    | vcpkg для zlib на Windows; системный/Homebrew либо отдельно собранный DjVuLibre | 🟡 | Qt внешний; DjVuLibre обязателен и не скачивается автоматически (см. `06-dev-setup.md`) |
  | HTTP          | QNetworkAccessManager           | ✅ используется | Запросы к LLM API (асинхронно через QFuture/QPromise) |
  | Изображения   | QImage                          | ✅ используется | Загрузка/отображение |
  | PDF           | **Qt PDF (`QPdfDocument`)**     | ✅ используется | Входит в поставку Qt6; без дополнительных нативных зависимостей (см. ADR #7) |
  | Ввод DjVu     | **DjVuLibre (`ddjvuapi`)** через `DjVuDocument` | Обязательная зависимость | Нативное декодирование страниц; CMake-цель `DjVuLibre::DjVuLibre`, GPL-2.0-or-later совместима с GPLv3 проекта LLocr (ADR 65) |
  | Отрисовка рамок | QML `Repeater` над списковой моделью | ✅ используется | Оверлей bbox поверх предпросмотра (нормализованные прямоугольники); блоки изображений можно перемещать / масштабировать / удалять |
  | Экспорт       | Прямой писатель (TXT/MD) + **рендер через конвейер предпросмотра** для HTML/PDF (`ExportRenderer`, headless WebEngine) + Pandoc для DOCX | ✅ готово | HTML/PDF совпадают с предпросмотром Markdown (marked + KaTeX); резервный встроенный `QPdfWriter` |
  | i18n          | Qt Linguist (`qsTr`/`tr` + `.ts`) | ✅ готово | Перевод на лету; язык сохраняется в `SettingsStore` (`ui/language`) |
  | Предпросмотр Markdown | Qt WebEngine + marked + KaTeX | ✅ готово | Переключатель в правой текстовой панели; ссылки на изображения разрешаются через data: URI |
  | Тесты         | Qt Test (модульные тесты в `tests/`) | ✅ готово | 4 базовые + 14 рантайм-целей (см. 4.12); вспомогательный `mock_llama_server` |
  | Локальный рантайм (управляемый llama.cpp) | `RuntimeController` + `LlamaServerProcess` + `ReleaseCatalog` | ✅ готово | Устанавливает и запускает локальный `llama-server` (см. §слой рантайма в «Архитектуре»); *HTTP-клиентом* остаётся `QNetworkAccessManager` |
  | Установка рантайма | `DownloadTask`/`DownloadManager` + `ArchiveExtractor` (zlib; zip + tar.gz) + `InstallTransaction` | ✅ готово | Докачиваемые загрузки, распаковка ZIP + `.tar.gz` (Windows получает zip, macOS/Linux — tar.gz), транзакционная установка (staging → проверка → переименование) |
  | Модели (Hugging Face) | `ModelCatalog` + `ModelRegistry` + `ModelInstaller` | ✅ готово | Установка GGUF с HF с закреплением за commit-SHA + `sha256` (`lfs.oid`) |
  | Пресеты моделей | `default-presets.json` + пользовательский `catalog.json` | ✅ готово | Заранее проверенные пары `model+mmproj+parser+prompt+ctx`; слияние по id |
  | Процессы без сирот | `ProcessGuard` (Job Object / `PDEATHSIG` / best-effort на macOS) | ✅ готово | Надёжно на Win/Linux, best-effort на macOS (owner.json + обнаружение при следующем запуске) |

  > **Примечание:** экспорт выполняется через **прямой постраничный писатель**
  > (TXT / Markdown) плюс **рендер через конвейер предпросмотра для HTML/PDF** —
  > headless `QWebEnginePage`, исполняющий тот же бандл marked + DOMPurify +
  > KaTeX, что и экранный предпросмотр, поэтому оба формата совпадают
  > с предпросмотром 1:1 (ADR 63). PDF печатается через
  > `QWebEnginePage::printToPdf` (A4) с резервным встроенным `QPdfWriter`;
  > **DOCX остаётся за Pandoc** (нативные формулы Word). Markdown остаётся
  > единственным внутренним источником истины.
  > Рендеринг PDF на *входе* использует модуль **Qt PDF** (`QPdfDocument`).
  > MuPDF остаётся резервным вариантом, если позже понадобятся более точный
  > или более быстрый рендеринг.
  >
  > Промпт модели **не** вводится свободно в `SettingsStore` — он принадлежит
  > выбранному **адаптеру OCR-модели** (`OcrModel::promptVariants()`; для
  > MinerU это обученные промпты задач из карточки модели, ADR 58).
  > Диапазон координат bbox — опция парсера (`ParserOptions::bboxRange`,
  > по умолчанию 1000).

  ## Управляемый локальный рантайм (llama.cpp) — этапы A–H ✅
  Начиная с готового бинарника llama.cpp или скачивая его из GitHub Releases
  (`ggml-org/llama.cpp`), приложение может запустить **локальный
  `llama-server`**, которым пользователю никогда не приходится управлять:

  | Аспект                | Выбор                                                                   |
  | --------------------- | ---------------------------------------------------------------------- |
  | Управляемый сервер    | **llama.cpp `llama-server`** (минимальная сборка `b4000`), запускается на loopback |
  | Установка рантайма    | GitHub Releases (`sha256` ассета из тела релиза), ZIP/**`.tar.gz`** через zlib |
  | Модели                | GGUF с **Hugging Face**, закреплённые за commit-`sha`, `sha256` из `lfs.oid` |
  | Живость               | GET `/health` (резерв `/v1/models`) во время запуска                    |
  | Загрузки              | `DownloadTask` (докачка: `.part`+`.part.meta`, `Range`/`If-Range`, потоковый sha256) в `DownloadManager` с очередью ≤2 |
  | Безопасность процессов | `QProcess` только через argv, `ProcessGuard` (Job Object / `PDEATHSIG` / best-effort) |
  | Воспроизводимость     | закреплённые теги сборок + закреплённые commit SHA, `sha256` проверяется перед использованием |

  > Локальный рантайм и модели не требуют **внешнего Python** и дополнительного
  > нативного инструментария — всё встроено (сеть через Qt, ZIP + `.tar.gz`
  > через zlib).

  ## Сервис RAG (отдельный процесс) — отложен (ADR 6), не начат
  Отдельный локальный Python-сервис (FastAPI + векторная БД), с которым LLocr
  мог бы общаться по HTTP. Отложен (ADR 6) — в текущий релиз не входит.

  ## Почему выбран такой стек
  - Не переучиваться ради самого переучивания — Qt покрывает все требования
    к GUI.
  - Python используется только там, где его экосистема действительно сильнее
    (отложенный сервис RAG).
  - Markdown как внутренний формат + Pandoc = дешёвая поддержка множества
    форматов экспорта.
  - Для **локального рантайма** самостоятельно управляемый llama.cpp (вместо
    Ollama/LM Studio) даёт один предсказуемый CLI и полный контроль над
    аргументами запуска — и никакой внешней зависимости для установки (ADR 27).
