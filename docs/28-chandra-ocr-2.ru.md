# Модель: Chandra-OCR-2

> Ручной запуск, контракт запросов и подключение в приложении. English
> version: `docs/28-chandra-ocr-2.md`. Карточка модели:
> <https://huggingface.co/datalab-to/chandra-ocr-2>.

## 1. Что это

**Chandra-OCR-2** — модель распознавания документов от DataLab:
дообученная Qwen3.5-VL-4B, которая читает страницу и отвечает
**HTML**. Обучена с двумя промптами:

| промпт | ответ | задача в приложении |
|---|---|---|
| `ocr_layout` | каждый блок обёрнут в `<div>` с `data-bbox` (0–1000) и `data-label` | **pageOcr** — распознавание с разметкой |
| `ocr` | тот же HTML без разметки | **rawPageOcr** — распознавание без разметки |

Оба промпта перенесены в профиль
(`resources/profiles/models/chandra-ocr-2.json`) дословно; источник
текста — референсный клиент (`chandra-ocr` на PyPI).

Модель — Qwen3.5-VL: тот же декодер, та же башня зрения и та же
гибридная рекуррентная память, что у fix-моделей Qwen3.5 в приложении,
поэтому флаги запуска, профиль памяти и проектор — из того же семейства.

## 2. Каким задачам она подходит

| задача | подходит | почему |
|---|---|---|
| **pageOcr** (OCR с разметкой) | **да** | промпт `ocr_layout` возвращает блоки с их рамками и метками — это распознавание с разметкой |
| **rawPageOcr** (OCR без разметки) | **да** | промпт `ocr` возвращает документ без разметки; страница — один текст, без блоков |
| **blockRecognition** (OCR одного блока) | **нет** | измерено: на кропе модель отвечает *страничной* задачей — `<div>` с рамкой всего кропа, обёрнутый в `$$…$$`, — то есть ответ не является текстом блока (ADR 145) |
| **decision** (проверка) | нет | протокол проверки — другое обучение (`/v1/systemone`, один ответ `noul`), модель на него не отвечает |
| **fix** (исправление) | нет | протоколу исправления нужен `OK`/`FIX`/`REVIEW`, а модель отвечает документом, а не вердиктом |
| **layout** (разметка без текста) | нет | промпт с разметкой всегда несёт текст вместе с рамками; отдельного промпта «только разметка» нет |

Задачу распознавания блока попробовали, прежде чем от неё отказаться: кроп
формулы вернулся так:

```
$$
<div data-bbox="10 10 990 980" data-label="Equation-Block">
<math display="block">\frac{p}{p_{\text{н.впр}}} \approx …</math>
</div>
$$
```

— страничный ответ на картинке с одним блоком, рамка закрывает весь кроп.
У модели нет обученного промпта для блока, а простой промпт разрешает
`data-bbox`/`data-label`, поэтому кроп возвращается документом с одним
блоком внутри. Читать это как текст блока — значит снимать обёртку
разметки, которую модель никогда не обещала: эвристика о причудах одной
модели, а не контракт. Поэтому роль не объявляется.

## 4. Запуск

Слои приложения (слой модели из профиля добавляет флаги к платформенным
`n-gpu-layers`/`flash-attn`/`ctx-size` и политике
`parallel`/`cache-reuse`/`no-context-shift`/`no-warmup`):

```
llama-server \
  --model <modelsDir>/prithivMLmods__chandra-ocr-2-GGUF/chandra-ocr-2.Q8_0.gguf \
  --mmproj <modelsDir>/prithivMLmods__chandra-ocr-2-GGUF/chandra-ocr-2.mmproj-bf16.gguf \
  --alias llocr-pageocr \
  --host 127.0.0.1 --port <auto> \
  --image-min-tokens 456 --image-max-tokens 6144 \
  --jinja --reasoning-budget 0 --temp 0 \
  --n-gpu-layers 99 --parallel 1 \
  --cache-reuse 0 --no-context-shift --no-warmup
```

- **`--jinja`** — модель обучена с тем шаблоном чата, который лежит в
  GGUF; встроенный шаблон его не воспроизведёт.
- **`--reasoning-budget 0`** — в шаблоне есть ветка размышления
  (`enable_thinking`); нулевой бюджет оставляет модель в режиме
  транскрибации. Модель пересказывает, а не рассуждает.
- **`--image-max-tokens 6144`** — собственный предел модели: референсный
  клиент масштабирует страницу не больше 3072×2048 пикселей, а это
  6144 image-токенов Qwen3.5-VL. Перед запросом страница масштабируется
  к тому же пределу (`imageLongestEdge: 2984` в профиле — тот же предел
  для страницы A4).
- **`--image-min-tokens 456`** — кроп блока растягивается до этого пола.
- ctx-size определяет машина (16384 на GPU-платформах): 6144 image-токенов
  + промпт + `max_tokens` 8192 в него помещаются.

## 5. Контракт запроса

Один запрос chat-completions на страницу: сообщение пользователя несёт
**сначала изображение, потом промпт** — тот порядок, который использует
референсный клиент (`chandra/model/vllm.py`).

```
[{"role": "user", "content": [
    {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,…"}},
    {"type": "text", "text": "<обученный промпт>"}
]}]
```

- Сэмплирование: `temperature 0.0`, `top_p 0.1` — настройки референсного
  клиента (жадное декодирование с узким ядром).
- `max_tokens` 8192 (`maxOutput` в профиле). Референсный клиент
  разрешает 12384; бюджет приложения помещается в окно контекста.
- Промпт берётся из роли: разметочный — для `pageOcr`, простой — для
  `rawPageOcr`. Модель, которая обслуживает обе задачи, отвечает на
  каждую своим промптом — задача доходит до профиля (роль у `OcrModel`).

## 6. Ответ

Промпт с разметкой отвечает одним `<div>` на блок:

```html
<div data-bbox="100 200 900 260" data-label="Section-Header">
  <h2>1. Introduction</h2>
</div>
<div data-bbox="100 300 900 500" data-label="Text">
  <p>Humans are remarkably adept at long-horizon tasks.</p>
</div>
```

- `data-bbox` — это `x0 y0 x1 y1`, нормализованные 0–1000.
- `data-label` — одна из собственных меток модели: `Text`,
  `Section-Header`, `Page-Header`, `Page-Footer`, `Caption`, `Footnote`,
  `Equation-Block`, `List-Group`, `Image`, `Figure`, `Diagram`, `Table`,
  `Code-Block`, `Form`, `Table-Of-Contents`, `Chemical-Block`,
  `Complex-Block`, `Bibliography`, `Blank-Page`.
- Перенос строки пишется как `<br/>` — тег закрывает сам себя. Ридер знает
  такой тег (ADR 224); прочитанный как обычный элемент, он поглотил бы весь
  остаток ответа.

Парсер (`src/parsers/ChandraParser.cpp`) превращает ответ в блоки
приложения:

- метка модели переводится в словарь меток приложения (`Section-Header`
  → `title`, `Equation-Block` → `equation`, `Caption` →
  `image_caption`, `Blank-Page` отбрасывается);
- рамка становится прямоугольником блока, нормализованным;
- содержимое становится Markdown: абзацы и списки — Markdown, таблица
  остаётся тем HTML, в котором пришла (её рисует стиль таблицы),
  `<math>` — `$…$` / `$$…$$`, `<img>` — описание из `alt`, чекбокс формы —
  `☐`/`☒`.

Формула в ячейке таблицы — тоже математическая разметка приложения: `$…$`,
а не тег `<math>`. Тег `<math>` для браузера — это MathML, и содержимое его
не рисуется (ADR 225).

Блок, который модель назвала `Equation-Block`, не всегда формула: это может
быть абзац с формулами. Парсер смотрит на содержимое — текст вне `<math>`
делает блок текстом, а не формулой (ADR 224). Формула с прозой обернулась
бы в `$$…$$` и не отрисовалась бы вовсе.

Ответ без разметки (простой промпт или модель, его проигнорировавшая)
становится текстом страницы без блоков — тот же запасной путь, что и у
остальных парсеров.

Задача **rawPageOcr** просит один текст, поэтому разметка отбрасывается,
даже если модель её выдала: задача, которой нужен текст, не должна
превращаться в страницу с разметкой. (Простой промпт разрешает
`data-bbox` и `data-label`, и на маленькой картинке модель их
использует.)

## 7. Настройки в приложении

- Задачи — **pageOcr** и **rawPageOcr** (окно «Модели»): модель можно
  выбрать для каждой из них.
- Установка через «Настройки → Модели» (репозиторий HF
  `prithivMLmods/chandra-ocr-2-GGUF`) или через шаг мастера с
  оборудованием.
- Парсер вывода — `chandra-ocr` (идентификатор, который объявляет
  профиль); его можно переопределить в настройках парсера.
- Внешний режим: любой OpenAI-совместимый сервер с этой моделью; разбор
  ответа остаётся тем же.

## 8. Известные ограничения

- Репозиторий GGUF — сторонняя упаковка (`prithivMLmods`), не сам
  DataLab: происхождение квантования — на упаковщике.
- Модель не обслуживает задачу блока (§2): кроп возвращается документом
  с одним блоком разметки, поэтому кнопке «Распознать» у блока нужна
  другая модель.
- Бюджет зрения и масштаб страницы выведены из правила референсного
  клиента (не больше 3072×2048 пикселей), а не измерены на железе
  приложения.
- Блок памяти переиспользует откалиброванные числа родственных моделей
  Qwen3.5 (тот же декодер и та же башня зрения); вес проектора — собственный
  модели.
