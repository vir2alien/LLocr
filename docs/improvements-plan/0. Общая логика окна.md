## 0. Общая логика окна

### Шапка с текущим состоянием над вкладками

text

```text
Unlimited-OCR · Q8_0                                 ● Запущена
2,9 ГБ на диске · ~6,5 ГБ памяти             Перезапустить
─────────────────────────────────────────────────────────────
Модель        Сервер        Генерация
```

Эта строка отвечает на главный вопрос сразу, на любой вкладке. Остальное содержимое окна служит для её изменения.

Названия вкладок:

- Location → **«Модель»**;
- Launch → **«Сервер»** (или «Запуск»);
- Request → **«Генерация»**.

Если интерфейс английский: *Model · Server · Generation*.

### Единая логика сохранения

Сейчас в коде она непоследовательная, и это важнее внешнего вида:

- `LocationTab` записывает пути в `Settings` сразу по `onEditingFinished`, а «Активировать» тоже применяется мгновенно. **Кнопка Cancel эти изменения не отменяет**, хотя остальные вкладки работают с черновиками.
- `Restore defaults` в подвале сбрасывает только Launch и Request, но показывается и на вкладке Location. Пользователь не может понять, что именно будет сброшено.

Есть два варианта исправления:

- **Вариант А:** выбор модели тоже становится черновиком и применяется по «Сохранить».
- **Вариант Б:** вкладка «Модель» применяет изменения сразу. Тогда на ней не нужны «Отмена» и «Сохранить», а их место занимает «Готово».

Я бы выбрал вариант А: так всё окно ведёт себя одинаково.

Общий «Restore defaults» лучше убрать из подвала. Вместо него у каждого раздела нужен свой сброс: «Сбросить к профилю». Если общий сброс всё же нужен, назовите его «Сбросить все параметры» и показывайте подтверждение.

### Предупреждение о перезапуске

Параметры сервера начинают действовать только после перезапуска llama-server. Как только на вкладке «Сервер» появились изменения, покажите полосу:

text

```text
ⓘ Изменения вступят в силу после перезапуска модели.   [Перезапустить после сохранения]
```
