# 01. Обзор проекта

> Английский оригинал: [docs/01-overview.md](01-overview.md)

## Идея
LLocr предоставляет удобный интерфейс, чтобы:
- подключаться к **LLM-эндпоинту, совместимому с OpenAI** (Ollama, LM Studio,
  llama.cpp server или любой размещённый OpenAI-совместимый API);
- выполнять OCR изображений и PDF с помощью мультимодальных LLM;
- сохранять и структурировать результат;
- выращивать базу знаний (RAG) из распознанных документов — **отложено
  (ADR 6), в текущий релиз не входит**.

## Целевые требования
1. **Кроссплатформенность** — Windows, macOS, Linux.
2. **Настраиваемые модель и вывод** — имя модели, параметры тела запроса
   и парсер вывода задаются пользователем (см. настройки), поэтому разные
   модели и форматы вывода поддерживаются без перекомпиляции. Промпт
   распознавания и парсер по умолчанию берутся от выбранного **адаптера
   OCR-модели** (например, `mineru`); новые LLM добавляются как
   классы-адаптеры. Для управляемого локального рантайма контекст
   предоставляют **пресеты моделей** (см. «Модели» ниже).
3. **Экспорт результата** — Markdown, DOCX (+ TXT, PDF, HTML).
4. **Интеграция RAG** — наполнение векторной базы данных из сканов.
   **Отложено (ADR 6)** — в текущий релиз не входит.
5. **Локализуемый и настраиваемый по темам интерфейс** — язык
   (System / English / Русский) и тема (System / Light / Dark) выбираются
   в настройках.

> **Примечание:** приложение ориентируется **только на OpenAI-совместимые
> подключения в стиле llama.cpp** (без отдельного слоя провайдеров — см.
> ADR 58). Все настройки модели/подключения/парсера редактируются в
> **диалоге настроек** и сохраняются через `QSettings`. **Промпт**
> распознавания принадлежит выбранному **адаптеру OCR-модели**
> (`OcrModel::promptVariants()`; MinerU использует обученные промпты задач
> из карточки модели).

## Пользовательский сценарий (MVP) — статус
1. Пользователь запускает локальный раннер LLM (Ollama / LM Studio /
   llama.cpp server), **устанавливает управляемый рантайм llama.cpp** или
   указывает на размещённый OpenAI-совместимый API.
2. В **настройках** (или в **мастере настройки** при первом запуске) он
   выбирает **режим подключения** — `External` (подключение к существующему
   серверу) или `Managed` (приложение запускает собственный сервер
   llama.cpp) — и настраивает URL эндпоинта, имя модели, API-ключ
   и (опционально) параметры генерации/парсера.
                                                                  ✅ готово (настройки с вкладками)
3. Он загружает одно или несколько изображений либо PDF.          ✅ готово (несколько изображений + PDF)
4. Он запускает распознавание.                                    ✅ готово (одна страница + «распознать всё»)
5. Он видит распознанный текст (+ ограничивающие рамки, если парсер
   работает с layout-токенами).                                   ✅ готово (панель текста + оверлей bbox)
6. Он сохраняет результат в нужном формате.                       ✅ (TXT/MD/HTML; DOCX через Pandoc; PDF)

## Локальный рантайм и модели (управляемый режим)
Помимо подключения к существующему OpenAI-совместимому серверу (`External`),
LLocr может **владеть всем рантаймом целиком** (режим `Managed`):

- **Мастер настройки при первом запуске** (шаги `Setup/`: Intro → mode →
  Hardware and models → Output → Check, ADR 170) доводит чистый профиль
  с нуля до распознанной страницы — терминал не нужен. Существующие профили
  считаются уже настроенными, и мастер **не** появляется (ADR 31).
- **Рантайм (llama.cpp):** в `Settings → Runtime` пользователь выбирает
  релиз + бэкенд (CPU / CUDA / Vulkan / Metal) и **скачивает и устанавливает**
  сборку `llama-server` из **GitHub Releases** (`ggml-org/llama.cpp`) —
  с проверкой `sha256` из тела релиза. Параметры запуска (`--port`,
  `--ctx-size`, `--n-gpu-layers`, `--alias`, `autoStart`) настраиваются
  в мастере / панели запуска.
- **Модели (Hugging Face):** в `Settings → Models` пользователь устанавливает
  **GGUF** vision-модели с Hugging Face (ревизия закреплена за коммитом
  `sha`, `sha256` из `lfs.oid`), выбирает управляемую модель из **каталога
  пресетов**, импортирует собственный каталог или указывает на локальный
  `.gguf`. Пресеты объединяют заранее проверенную пару
  `model + mmproj + parser + prompt + ctx-size`.
- **Распознавание:** в режиме `Managed` LLocr автоматически запускает
  `llama-server` на localhost, ждёт `/health`, запрашивает `/v1/models`
  и разрешает подключение — распознавание и ручные Start/Stop/Restart идут
  через единственный фасад `RuntimeController`.

## Описание интерфейса (текущая реализация)
Окно использует компоновку **панель инструментов + три области**.

- **Панель инструментов** — открыть, распознать, распознать всё, остановить,
  навигация по страницам (‹ n / N ›), экспорт и **настройки**.
- **Лента слева** — миниатюры страниц для многостраничных документов; каждая
  несёт маркер **распознана / не распознана**, маркер **изменена** и маркер
  **дубликата** (красный). Страницы можно **удалять** и **переставлять
  перетаскиванием**. Клик по миниатюре переключает на эту страницу (работает
  даже во время распознавания). Блоки здесь не рисуются.
- **Центральная область** — полный предпросмотр текущей страницы с **оверлеем
  ограничивающих рамок**, когда активен layout-token-парсер. Блоки
  изображений/диаграмм можно **перемещать, масштабировать и удалять** прямо
  на предпросмотре.
- **Правая область** — распознанный текст текущей страницы, **редактируемый**,
  как только страница распознана, с переключателем **Предпросмотр**, который
  отображает текст как Markdown (через Qt WebEngine + marked + KaTeX).

## Настройки (окна)
Отдельные немодальные окна, открываемые из меню в шапке (ADR 70):
**Интерфейс** · **Вывод** · **Проверка** · **Рантайм** · **Модели**
(раньше — вкладки UI / Connection / Model / Output / Runtime / Models
диалога с вкладками).

- **Интерфейс** — язык (System / English / Русский), тема (System / Light / Dark).
- **Подключение** — базовый URL эндпоинта, API-ключ (опционально), таймаут
  запроса. **Режим** распознавания (`External` / `Managed`) выбирается
  мастером первого запуска; существующие профили по умолчанию остаются
  на `External` (ADR 26/31).
- **Модель** — имя модели, температура, максимум токенов и **параметры
  сэмплирования DRY** (multiplier, base, allowed length, penalty last-N).
  В режиме `Managed` идентификатор/алиас модели вычисляется рантаймом,
  а не вводится вручную.
- **Вывод** — адаптер OCR-модели (`model/recipeId`, по умолчанию `mineru`)
  и парсер вывода (`Automatic` / `raw` / парсер layout-разметки
  `mineru-layout`; по умолчанию `auto`, ADR 88 и 112).
- **Рантайм** — путь до бинарника управляемого `llama-server` + проба,
  Start/Stop/Restart, **Показать журнал** и **установщик этапа D** (выбор
  релиза и бэкенда, «Скачать и установить» с прогрессом,
  «Установлено: bXXXX (CUDA)», «Проверить обновления», «Очистить
  неиспользуемые сборки»).
- **Модели** — таблица установленных моделей (активировать/удалить),
  **каталог пресетов**, поиск и скачивание на Hugging Face, HF-токен,
  импорт/экспорт каталога, проверка GGUF.

> **Промпт** распознавания принадлежит выбранному **адаптеру OCR-модели**
> (`OcrModel::promptVariants()`; для MinerU это обученные промпты задач
> из карточки модели, ADR 58) и не редактируется в диалоге. **Парсер** вывода
> **по умолчанию — тот, что объявляет адаптер модели**
> (`OcrModel::defaultParserId()`), поэтому смена модели не может оставить
> неподходящий парсер; диапазон координат bbox — опция парсера
> (`ParserOptions::bboxRange`, по умолчанию 1000), а не настройка.
>
> **Секреты:** API-ключ и HF-токен живут в **хранилище секретов ОС** —
> macOS Keychain, Windows Credential Manager, Linux Secret Service (ADR 227).
> Файл настроек хранит только эндпоинты и алиасы; старый ключ в открытом виде
> мигрируется при запуске и удаляется из файла. Сохранённый ключ никогда
> не показывается обратно: поле несёт маску и принимает новый. Секреты никогда
> не попадают в журналы, сообщения об ошибках, предпросмотр команды или файл
> проекта.
