# Модель: MiniCPM-OCR 1.0

> Ручной запуск, контракт запросов и проводка в приложении. Английская
> версия: `docs/30-minicpm-ocr.md`. Сопутствующая decision-модель
> (визуальная сверка) — MiniCPM-OCR Jev, `docs/31-minicpm-jev.ru.md`.

## 1. Что это

**MiniCPM-OCR 1.0** (OpenBMB, 1,3 млрд параметров) — первая OCR-модель
семейства MiniCPM-V/o: сиглиповский энкодер зрения + языковой ствол
Qwen3.5 (24 слоя, из них 6 полного внимания), обученная на разборе
текстоцентричных документов — текст, таблицы, формулы, диаграммы, печати —
для китайских и английских документов. Заявлено 93.68 на
Real5-OmniDocBench. Лицензия Apache-2.0.

Разметку страницы в родном пайплайне делает отдельная модель
(PP-DocLayoutV3), в GGUF она **не входит**, поэтому в LLocr модель несёт
**blockRecognition** и **rawPageOcr** — устройство GLM-OCR. Роли разметки у
нее нет: разметку ведут teleocr или mineru.

## 3. Запуск

Профиль несет пять флагов на роль (обе роли объявляют одинаковый список —
переключение задачи не перезагружает модель):

```
llama-server \
  --model <modelsDir>/openbmb__MiniCPM-OCR-1.0-gguf/MiniCPM-OCR-1_0-Q8_0.gguf \
  --mmproj  <modelsDir>/openbmb__MiniCPM-OCR-1.0-gguf/mmproj-model-f16-4x.gguf \
  --model-draft <modelsDir>/openbmb__MiniCPM-OCR-1.0-gguf/dspark-MiniCPM-OCR-1_0-F16.gguf \
  --alias llocr-blockrecognition \
  --host 127.0.0.1 --port <auto> \
  --n-gpu-layers 99 --parallel 1 --cache-reuse 0 --no-context-shift \
  --flash-attn on \
  --reasoning off \
  --spec-type draft-dspark --spec-draft-n-max 15 --spec-draft-n-min 0
```

Два флага — требование самой модели, а не настройка:

- **`--reasoning off`** (llama.cpp PR #30979). Модель пишет транскрипцию
  **внутри thinking-блока**: с умолчательным `auto` ответ приходит с пустым
  `content`, а текст лежит в `reasoning_content`, который приложение
  читает как пустой ответ. (Шаблон чата в GGUF уже отключает генерацию
  мыслей; этот флаг переносит ответ в `content`.)
- **`--spec-type draft-dspark`** + два флага бюджета. Драфтер DSpark — тот
  же механизм, что у LFM2.5 (абсолютная таблица целевых токенов `d2t`);
  драфтер обучен с блоком 16 — в родной конфигурации vLLM стоит
  `num_speculative_tokens: 15`. DSpark требует главную модель и драфт из
  одного релиза.

Без `--image-min-tokens`/`--image-max-tokens`: проектор MiniCPM режет
картинку на слайсы сам (до 9 слайсов по 448 px, 4×-даунсемпл — порядка
2560 визуальных токенов на плотной странице), и родной гайд запуска
бюджетных флагов не ставит.

## 4. Контракт запросов

- Задачу выбирает обученный префикс, и промпт обязан соответствовать кропу
  (карточка базовой модели): `Text Recognition:` — текст/абзац/заголовок/
  страница, `Table Recognition:` — таблицы, `Formula Recognition:` —
  выключные формулы, `Seal Recognition:` — печати. Роль blockRecognition
  отображает типы блоков приложения на эти четыре; rawPageOcr отправляет
  страницу с `Text Recognition:`.
- Ответ — текст и больше ничего, читается парсером `raw` (устройство
  GLM-OCR). Таблицы выходят HTML (в SDK их дочищает пост-обработка),
  формулы — LaTeX с разделителями `$…$`/`$$…$$`.
- Сэмплинг: `temperature 0`, нейтральные штрафы, `stream false`,
  `cache_prompt true`.
- KIE (извлечение полей в JSON-объект) и `Chart to Table:` — обученные
  промпты, которые профиль сознательно **не подключает**: задач для них в
  LLocr нет.

## 5. Верификация

Распознанные блоки идут через обычный конвейер decision/fix. Сопутствующая
модель оценки качества **MiniCPM-OCR Jev** (docs/31) обучена на разборах
именно MiniCPM-OCR 1.0 — пара из них и есть задуманная конфигурация.

## 6. Настройки в приложении

- Задачи — **blockRecognition** и **rawPageOcr** (окно «Модели»);
  умолчания задач остаются за glm-ocr.
- Установка через «Настройки → Модели» (репозиторий HF
  `openbmb/MiniCPM-OCR-1.0-gguf`) или шаг «Оборудование» мастера; драфтер
  скачивается вместе с моделью сам.

## 7. Известные ограничения

- **Нет разметки.** PP-DocLayoutV3 в GGUF не входит — профиль сознательно
  не объявляет задачу layout.
- **Только китайский и английский.** Модель обучена на документах zh/en;
  прочие языки вне распределения.
- Спекулятивное декодирование DSpark точно только при жадном
  декодировании — температура в профиле закреплена на нуле.
- Q4_K_M может ронять косые черты закрывающих тегов на страницах,
  плотных кодом/XML (таблица квантований карточки) — для таких страниц
  лучше q8_0.
- Блок `memory` профиля — оценка, откалиброванная на CPU-пробе
  (docs/27 §4–5); при смене флагов запуска перегоните
  `scripts/measure-memory.sh`.
