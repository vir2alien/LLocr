# Модель: Qwen3-VL-4B / Qwen3-VL-8B

> Ручной запуск, контракт запросов и подключение в приложении. English
> version: `archive/models/docs/31-qwen3-vl.md`.

## 1. Что это

**Qwen3-VL-4B** и **Qwen3-VL-8B** (Qwen, Instruct, Apache-2.0) — универсальные
зрительно-языковые модели. В LLocr они закрывали задачу **fix** — исправление
уже распознанного блока — и задачу чтения («Распознать (LLM)»), которая
переписывает блок по одной картинке, без опорного текста.

Пара вырезана по **ADR 335**: качество и скорость не удержались на замерах, а
задачу исправления остаются на семействах Qwen3.5 и Gemma-4. Профили и
собственная формулировка читателя сохранены здесь целиком.

## 3. Запуск llama-server

Одна конкретная команда — **Qwen3-VL-4B** на **macOS · Metal** (платформенный
профиль `macos-metal`), ровно как её собирает
`ServerLaunchConfig::toArguments` (`src/runtime/ServerLaunchConfig.cpp`):
сначала поля ядра, затем параметры по порядку:

```
llama-server \
  --model <modelsDir>/Qwen__Qwen3-VL-4B-Instruct-GGUF/Qwen3VL-4B-Instruct-Q8_0.gguf \
  --mmproj <modelsDir>/Qwen__Qwen3-VL-4B-Instruct-GGUF/mmproj-Qwen3VL-4B-Instruct-F16.gguf \
  --alias llocr-fix --host 127.0.0.1 --port 8080 \
  --parallel 1 --cache-reuse 0 --no-context-shift --no-warmup --verbosity 3 \
  --n-gpu-layers 99 --flash-attn on --ctx-size 16384 \
  --temp 0 --jinja --image-min-tokens 1024
```

Три слоя сводятся в `LaunchProfileStore::compose`: **политика**
(`serverLaunch.json → policy.parameters`), **платформа**
(`serverLaunch.json → profiles[macos-metal]`) и **модель**
(`qwen3-vl-4b.json → roles.fix.launch`).

| Флаг | Значение | Слой | Зачем |
| --- | --- | --- | --- |
| `--model` / `--mmproj` | пути | ядро | веса и проектор; без `--model-draft` |
| `--alias` | `llocr-fix` | ядро | alias роли; поле `model` запроса маршрутизирует по нему |
| `--host` / `--port` | `127.0.0.1` / выбрать | ядро | настройки по умолчанию (`127.0.0.1`, `0` = выбрать самому) |
| `--parallel` | `1` | политика | один слот декодирования |
| `--cache-reuse` | `0` | политика | переиспользование контекста между запросами выключено |
| `--no-context-shift` | флаг | политика | контекст не сдвигается; KV не переносится при переполнении |
| `--no-warmup` | флаг | политика | прогрев при загрузке пропускается |
| `--verbosity` | `3` | политика | уровень лога сервера |
| `--n-gpu-layers` | `99` | платформа | все слои на GPU |
| `--flash-attn` | `on` | платформа (переопределён моделью) | ядра flash attention; нужны зрительному стеку |
| `--ctx-size` | `16384` | платформа | окно промпта + картинки + ответа (8192 на профиле CPU) |
| `--temp` | `0` | модель | серверный жадный режим; исправления должны быть детерминированными |
| `--jinja` | флаг | модель | chat-шаблон из метаданных GGUF |
| `--image-min-tokens` | `1024` | модель | llama.cpp предупреждает, что Qwen-VL нужно минимум 1024 токена изображения для grounding-задач |

**8B требует того же набора флагов**; различается только бюджет памяти
(автовыбор в мастере спускается на меньшие кванты, чтобы влезть).

## 4. Сборка запроса

Транспорт: `FixModel` поверх `VisionChatModel` (`src/models/`),
`POST /v1/chat/completions`, один запрос на блок, `stream: false`. Системный
промпт и промпт типа приходят из общего профиля запросов `fix-requests.json` —
своей формулировки для задачи fix пара не несла, отвечали общие тексты
(ADR 182). Картинка — кроп блока PNG в data URL; кандидат — действующий текст
блока, формула уже в каноническом LaTeX (ADR 194).

**Протокол исправления** (`full_block`): ответ — `OK`, `FIX` с исправленным
блоком или `REVIEW`; всю первую строку занимает ключевое слово (ADR 332).
Параметры запроса, которые несут профили:

| Параметр | Значение | Зачем |
| --- | --- | --- |
| `temperature` | `0.0` | детерминированное жадное декодирование |
| `repeat_penalty` | `1.0` | штраф за повторы выключен |
| `presence_penalty` | `0.0` | нейтрально |
| `frequency_penalty` | `0.0` | нейтрально |
| `stream` | `false` | парсеру нужен один целый ответ |
| `cache_prompt` | `true` | промпт (системное сообщение, эмбеддинги картинки) переиспользуется между блоками — плотная модель может, в отличие от гибридно-рекуррентного семейства fix |
| `stop` | `["</CANDIDATE>"]` | только маркер протокола: end-of-text в списке stop сверяется с самим ответом и обрезает его в пустоту (ADR 249) |

`maxOutput` — 8192 токенов у обеих ролей.

## 5. Задача чтения: собственный читатель семейства

Пара была единственным семейством в поставляемом каталоге, у которого была
**собственная формулировка читателя** (`readSystemPrompt` в роли): общий
контракт чтения (`read-requests.json`) плюс одна фраза собственной калибровки
семейства — «Read glyphs at the printed size; never guess small print.»

Причина — замер (ADR 267): семейство читало общую формулировку как
проверку исправления и отвечало `REVIEW` на **каждом** разборчивом блоке.
Своя формулировка это чинила; ADR 334 потом переписала её в контракт чтения,
так что переопределение было общим контрактом плюс фраза про мелкий шрифт и
ничем больше.

Остальное чтение — общее: запрос это ровно картинка блока, системный промпт и
промпт блока — опорный текст не едет вовсе (ADR 266), — а ответом является
текст блока, единственный вердикт — `REVIEW` (ADR 331).

4B и **12.84 ГБ** для 8B.

## 7. Настройки в приложении

- Задача — **fix** (окно «Модели»); дефолт задачи — `qwen3.5-4b` (ADR 252).
- Пара не несла флага `default`: она предлагалась в списке fix, но никогда не
  выбиралась автоматически.
- Установка через Настройки → Модели (репозитории Hugging Face из §2) или через
  шаг железа в мастере, который подбирает модель-дефолт роли под 0.9 × (VRAM ‖ RAM).

## 8. Ограничения

- **Нет размышления.** У Instruct-линии нет канала thinking, поэтому роли
  объявляют `reasoning: false`, и задача исправления не тратит на них бюджет
  размышления (ADR 268).
- Лаунчеру нужен llama.cpp **b9263** или новее.
- Формулировка читателя семейства была единственной такого рода в
  поставляемом каталоге; все остальные fix-модели брали общего читателя
  (ADR 267).
