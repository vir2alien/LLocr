# OCRtest — тестовый корпус и результаты оценки decision-моделей

Корпус для измерения качества верификации распознанного текста
(decision-модель, `/v1/systemone`) и финальные результаты замеров
13–14.10.2026. Сам стенд живёт в `scripts/decision-eval`, описание
исследования и выводы — `docs/17-d1-verification-study.md`.

## Состав

| путь | что это |
|---|---|
| `TEST.llocr` | проект приложения: 11 страниц, 221 блок с распознанным текстом и нормализованными bbox (источники вложены в ZIP) |
| `*.png`, `*.pdf` | исходные документы корпуса (те же, что внутри TEST.llocr, в оригинальном виде) |
| `labels.json` | шаблон ручной разметки: `uid → "wrong" / "unsure" / ""` — помеченные `wrong` блоки становятся классом `real_ismatch` при прогоне |
| `work/results/report.md` | итоговый отчёт: рейтинг схем запроса, пороги, разбивка по типам блоков и моделям (d1-3B и clef-flash) |
| `work/results/cases.csv` | построчная запись каждого запроса (6 020 успешных): вариант схемы, класс кейса, вероятность, токены, латентность |
| `work/results/probe.json` | зафиксированные форматы ответов `/v1/systemone` (noul/choice/score) сборки llama.cpp b11564 |

Промежуточные данные (кеш ответов, отрендеренные страницы, распакованный
проект, скачанные GGUF, логи сервера) в репозиторий не входят и при прогоне
создаются заново в `work/`.

## Как воспроизвести

```sh
cd scripts/decision-eval
python3 -m venv .venv
./.venv/bin/pip install pymupdf pillow matplotlib
./.venv/bin/python run.py --stage all        # clef-flash (decision), полная последовательность
```

Требования: установленная модель (пути в `configs/*.json`), свободный GPU
(приложение LLocr и его сервер должны быть закрыты). Подробности —
`scripts/decision-eval/README.md`.
