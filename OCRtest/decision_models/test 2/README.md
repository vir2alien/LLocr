# Тест decision-моделей (corpus OCR_TEST, блоки теплообменников)

Один и тот же результат распознавания **MinerU2.5-Pro** (195 блоков, 10 страниц —
статья про Unlimited OCR + русская техническая литература про теплообменники с
формулами и таблицами) проверяется decision-моделями. Прогон каждой итерации
правок профилей — своя подпапка с `.llocr`-проектами; в корне лежит исходный
проект распознавания (без вердиктов — evaluate.py пропускает его сам):

```
OCR_TEST_MinerU2.5-Pro.llocr   ← исходное распознавание (не оценивается)
iteration1/                    ← базовый прогон 18.10 (clef v5, d3 v6, старые промпты)
iteration2/                    ← 19.10: clef переведён на v6, промпты по рекомендациям
evaluate.py, truth.json, README.md
```

Папка — самодостаточный стенд: правите промпты/пороги профиля → перегоняете
проверку в приложении → кладёте новый `.llocr` в новую подпапку `iterationN/` →
одна команда даёт FP/FN по типам блоков. Код приложения не требуется.

## Быстрый прогон

```sh
cd "OCRtest/decision_models/test 2"
python3 evaluate.py                # все итерации разом, консенсус по каждой подпапке
python3 evaluate.py iteration2     # только одна итерация
python3 evaluate.py --verbose      # + списки FN/FP с расхождениями и причинами
python3 evaluate.py --json out.json
```

Зависимости: `python3`, `pip install rapidfuzz`. Эталон берётся из
`../../ocr_models/materials` (gt.json + gt.py + compare.py); при другом
расположении — `--materials PATH`. Новая модель = ещё один
`OCR_TEST_<имя>.llocr` с **тем же** распознаванием в подпапке итерации.

## Методика

1. **Истина** — ручная поблочная транскрипция из `OCRtest/ocr_models`
   (эталон снят с 200-dpi рендеров, включая строки-«огрызки» соседних блоков;
   спорные места сверялись с кропами и рендерами).
2. **Критерий ошибки** — правила эквивалентности из самих профилей
   (`resources/profiles/models/*.json`): гомоглифы (н/H, ν/v, ρ/p), е/ё,
   регистр, потерянные штрихи/черты, лишняя/пропавшая пунктуация и фрагменты —
   **ошибка**; carrier-разметка (`\( \)`, `\tag{n}`, `\mathrm`/`\mathbf`,
   `\left`/`\right`, переносы `\\`, конвенции индексов `T_f1` vs `T_{f1}`) —
   **не ошибка** (при рендере её не видно).
3. Сравнение — нормализация `compare.py` (+ досечение `\(...\)` в текстовых
   блоках) и посимвольный CER. `CER>0` = ошибка, кроме явно перечисленного в
   `truth.json` (`clean_overrides`, каждый — с причиной).
4. **Вердикты**: статус бокса в `BoxCheckStatus` приложения: 0 = вне области
   проверки (исключён), 1 = Ok, 3 = Review (пустой/нечитаемый кроп),
   4 = Mismatch (fixable). Флаг = всё, что не Ok/0. FP = флаг на чистом блоке,
   FN = Ok на блоке с ошибкой. FN% считается от блоков с ошибками, FP% — от
   чистых.
5. **Свежесть истины**: `truth.json` хранит sha1 текста каждого блока. Если
   распознавание сменилось (другая OCR-модель или новая разметка), блоки с
   изменившимся текстом исключаются из оценки с предупреждением — их надо
   переразобрать (`--verbose`, решение занести в `clean_overrides` при
   необходимости). При правках **decision-промптов** тексты не меняются и
   истина остаётся валидной без дополнительных действий.
6. **Калибровка порогов по confidence** (ADR 173): прогоны, сделанные сборкой
   с сохранением confidence, печатают под каждой моделью кривую FN/FP(t).
   Направление: Ok = p ≥ t, поэтому **выше порог — меньше FN и больше FP**
   (снижение порога наоборот разменивает FP на FN). Кривая пересчитывает
   вердикт из сохранённого P(match): флаг при p < t, Review — флаг при любом t;
   Mismatch по диагнозу (fixable при высокой p) кривая не видит и слегка
   завышает FN. Одна сборка даёт всю кривую — перебор итераций не нужен.

### Главные паттерны

- **FN**: доминирует курсивное `и↔н` в русском тексте (~30 блоков, ловится
  наполовину; clef на простом русском — 8 пропусков из 11). Общие слепые зоны:
  `∂`→`d` и `ρ`→`p` в текстовых блоках (текстовые промпты не описывают
  математику), потеря `ё`, штрихов (`Bi′`), черт (`ū`), огрызка строки
  (`ν=η/ρ`), у d3 — замены интегралов `∯`→`∬`, `∭`→`∬∬`.
- **FP**: clef флагает верную разметку `\tag`, `\mathrm`, `\left/\right` в
  формулах (11 из 21 FP); d3 — `\( \)`-обёртки в текстовых блоках (per-block
  statePrompt замещает ролевой и теряет правило «LaTeX — carrier»); d3-mini —
  короткие заголовочные строки, дословно совпадающие с кропом; clef — блок,
  начинающийся с середины слова.
- **Таблицы**: clef флагает все 9 (в т.ч. 3 верные); d3 пропускает латинизацию
  в ячейках (`моль/(м³·с)` → `(m³·c)`, ν→v, `\tilde` вместо черты).

### Рекомендации по промптам (проверяются этим стендом)

1. Вернуть «LaTeX/`\(...\)` — carrier» в каждый блочный statePrompt d3
   (`blockPrompts.*.statePrompt` замещает ролевой промпт).
2. Добавить правило и/н (курсивная печать) во все профили — крупнейший класс FN.
3. В equation-промпты: различия интегралов ∯/∬/∭, ρ/p, ν/v, ∂/d; пропавший
   фрагмент/пунктуация — ошибка; `\tag{n}` ≡ `(n)`.
4. В текстовые промпты: гомоглифы и диакритика в инлайн-математике (ρ/p, ν/v,
   π/п, φ/ф, ū, ′) — контент.
5. d3-mini: «короткая строка, дословно совпадающая с кропом — exact_match».
6. Пороги: Ok = p ≥ t, поэтому направление «дешёвых» FN — пороги **вверх**
   (каждый шаг вверх конвертирует часть TN в FP, но ловит ошибки из
   вероятностного хвоста). Базовая рекомендация дана до персистенции
   confidence; точную точку выбирать по кривой FN/FP(t) из evaluate.py.

## Ограничения

- Вердикты сравниваются с изображением кропа; эталон — ручная транскрипция как
  прокси. Спорные случаи адьюдикации сверены с кропами/рендерами; случаи
  «только начертание» (жирное `g` в тексте, `\mathrm` у формулы с жирным
  шрифтом в изображении) отнесены к «чистым» — это и есть FP clef на формулах.
- Статус 4 в проектах — это **Mismatch** боксового enum (`BoxCheckStatus`:
  0 NotChecked, 1 Ok, 3 Review, 4 Mismatch); Review (3) в прогонах не
  встречался — пустых/нечитаемых кропов в корпусе не было. Скрипт считает
  флагом и то и другое.
- Числитель/знаменатель: FP% = FP / чистые блоки, FN% = FN / блоки с ошибками;
  абсолютные значения в скобках.
