# iteration8 — калибровка порогов MiniCPM-OCR Jev (visual diff)

Первое измерение порогов decision-задачи на visual-diff протоколе (`systemone_visual_diff_v1`,
docs/31 §6 — пункт «калибровка не сделана» закрыт). Прогон: то же распознавание
MinerU2.5-Pro (195 блоков, 177 в области проверки), решает **MiniCPM-OCR Jev Q8_0**,
запрос приложения бит в бит — кроп 300 dpi + **рендер кандидата собственным
`CandidateRenderer` приложения** (ADR 184: порог измеряется против запроса, который
уходит на провод; чужой рендер сдвигает шкалу — docs/31 §3).

## Как сделан прогон

1. **Рендеры кандидата** — `tests/candidate_render_dump.cpp` (вспомогательная цель
   `candidate_render_dump`, не тест): загружает `minicpm-ocr-jev.llocr`, считает
   отображаемый текст (`renderBlockText` + `blockStyleForLabel`, модель mineru,
   `tablesAsHtml=false`) и снимает каждую картинку через `CandidateRenderer` headless
   (offscreen + встроенный `/preview`). 177 PNG + `manifest.json` (state = текст блока
   как есть) в `../jev-runs/renders/`.
2. **Кропы** — `corpus.py` стенда (300 dpi, математика обрезки совпадает с
   `AppController::croppedImage`; сверена бит в бит на этом корпусе в iteration7).
3. **Запросы** — `../jev_score.py`: POST `/v1/systemone`
   `{state: <текст блока>, images: [кроп, рендер], questions: {match: noul}}`,
   llama.cpp **b11946** (vulkan), флаги из профиля (`--ctx-size 16384 --batch-size 2048
   --ubatch-size 512 --flash-attn on --parallel 1 --cache-reuse 0 --no-context-shift`),
   лог `../jev-runs/server.log` (`decision model type: openbmb-minicpm-ocr-jev`).
   P(match) каждого блока — в `../jev-runs/scores.json`; вердикты при t=0.5 — в
   `OCR_TEST_minicpm-jev.llocr` (evaluate.py считает его обычным прогоном).
4. Оценка — `evaluate.py iteration8`, кривые и пороги — `../jev-runs/calibrate_jev.py`
   (та же логика, что `decision-calibrate.py` + `pick-thresholds.py`, но с путями после
   переноса стенда в `archive/`). Отпечатки `truth.json` совпадают 195/195 — истина
   валидна без переразбора.

## Результат

73 блока с ошибками, 104 чистых, 18 вне области проверки. При профильном 0.5:

| корзина | ошибок/чистых | AUC | FN / FP при 0.5 |
|---|---|---|---|
| Формулы | 20/30 | 0.788 | 12 / 1 |
| Таблицы | 6/3 | 0.500 | 0 / 3 |
| Текст с формулами | 34/37 | 0.862 | 12 / 5 |
| Простой текст | 11/11 | 0.868 | 5 / 1 |
| Служебные | 2/23 | 1.000 | 0 / 5 |
| **Итого** | 73/104 | | **29 (39.7 %) / 15 (14.4 %)** |

Кривые FN/FP(t) по типам (Ok = p ≥ t; FN↑FP↓ при росте порога) — полный вывод
`../jev-runs/calibrate-iteration8.txt`. Пороги выбраны коленом кривой типа (правило
стенда, rate=1.0: последняя ступень, где одна пойманная ошибка стоит не больше одного
FP; FP=0 — край чистой области):

| тип | err/clean | кривая (сетка 0.01, фрагмент) | порог | FN/FP при нём |
|---|---|---|---|---|
| text | 45/52 | 0.80: 9/13 · 0.90: 6/21 · **0.92: 5/24** · 0.95: 1/29 | **0.92** | 5 / 24 |
| equation | 20/30 | 0.80: 7/4 · 0.85: 6/7 · **0.87: 5/10** · 0.90: 4/15 | **0.87** | 5 / 10 |
| table | 6/3 | 0/3 на всей сетке (все p < 0.02) | **0.40** | 0 / 3 |
| остальные (base) | 2/19 | FN 0 на всей сетке | 0.50 (без изменений) | 0 / 4 |

**Итого при новых порогах: FN 10 (13.7 %) / FP 41 (39.4 %)** — против FN 29 / FP 15
у 0.5: 19 ошибок пойманы ценой +26 блоков на перепроверку. Для сравнения на этом же
корпусе: d3-mini FN 12 / FP 22, clef-flash FN 22 / FP 25, d3-flash FN 34 / FP 7
(iteration7) — Jev с этими порогами пропускает меньше всех, платя наибольшим числом
перепроверок.

Чувствительность к правилу (только калибруемые типы):

| rate | text | equation | FN / FP |
|---|---|---|---|
| 0.5 | 0.90 | 0.71 | 15 / 30 |
| **1.0 (выбрано)** | **0.92** | **0.87** | **10 / 41** |
| 2.0 | 0.95 | 0.87 | 6 / 45 |

## Что показало измерение

1. **Таблицы модель отвергает целиком**: все 9 блоков (чистые и ошибочные) имеют
   p = 0.0006–0.019. Markdown-сетка рендера — вне распределения модели (upstream
   обучал таблицы на своём рендере). Разделения нет (AUC 0.5), порог не влияет:
   при любом t ∈ [0.02, 0.98] все таблицы уходят в Mismatch. Выбрано 0.40 (край
   измеренной области) — поведение «флаговать все» сохранено сознательно: 6 ошибок
   не проходят мимо, цена — 3 ложные тревоги. Это находка про связку «Jev + рендер
   приложения», а не про порог.
2. **FP-хвост на тексте структурный.** Чистые текстовые блоки бимодальны: 26 блоков
   в 0.95–1.0 и ~24 в 0.09–0.92. Низкий хвост — не шум модели: на «машописных»
   страницах (стр. 1/4/5 корпуса) рендер пере-верстает абзац под свою ширину
   (6 строк кропа → 4 строки рендера), переносы «вектор-/ра» оказываются на других
   позициях, шрифт другой — модель видит другую картинку и честно отвечает «не
   сходится» (пример: p4b20, текст совпадает с эталоном посимвольно, p = 0.088).
   Порог этот хвост не уменьшает — он лежит на 0.5–0.9 равномерно с ошибками.
3. **Остаточные 10 FN — жёсткое ядро**, тот же класс, что у текстовых моделей:
   гомоглифы печати (н→и, и→И, Π→II, ρ→p, г→r, б→6), интегралы (∯→∬, ∭→∬∬),
   потерянная черта ū, потерянная пунктуация, замена «дли»→«протяже». Визуальному
   диффу они недоступны — ничего не меняется от порога.
4. **Служебные типы** (title, table_caption, table_footnote, list, image_caption):
   обе ошибки корпуса имеют p ≈ 0 (ловятся любым порогом), чистые — от 0.10 до 0.99;
   base 0.5 оставлен без изменений (FN 0 / FP 4; калибровать отдельные записи
   оснований нет — поведение не меняется).
5. Блок p7b2 (большая таблица, запрос ~8k токенов) отвечает 309 c — дольше
   стандартного таймаута клиента; в приложении такой блок уходит на Review с
   записью в футере, не в тихий Ok.

## Воспроизведение

```sh
# 1) рендеры кандидата (один раз; цель добавляется в tests/CMakeLists.txt)
cmake --build build/win-msvc2022 --target candidate_render_dump
QT_QPA_PLATFORM=offscreen build/win-msvc2022/bin/candidate_render_dump.exe \
  --project OCRtest/decision_models/minicpm-ocr-jev.llocr \
  --out "OCRtest/decision_models/test 2/jev-runs/renders"

# 2) сервер (модели в %APPDATA%/llocr/LLM OCR)
cd "%APPDATA%/llocr/LLM OCR/runtime/llama.cpp-b11946-vulkan-win-x64"
llama-server.exe --model ../../models/openbmb__MiniCPM-OCR-Jev-gguf/MiniCPM-OCR-Jev-Q8_0.gguf \
  --mmproj ../../models/openbmb__MiniCPM-OCR-Jev-gguf/mmproj-model-f16.gguf \
  --alias llocr-decision --host 127.0.0.1 --port 18999 --n-gpu-layers 99 --parallel 1 \
  --cache-reuse 0 --no-context-shift --ctx-size 16384 --batch-size 2048 \
  --ubatch-size 512 --flash-attn on

# 3) прогон и оценка
cd "OCRtest/decision_models/test 2"
py -I jev_score.py
py -I evaluate.py iteration8
py -I jev-runs/calibrate_jev.py
```
