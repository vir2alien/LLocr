# Отчёт: сравнение OCR-моделей на блочном распознавании (OCR_TEST)

**Дата:** 17.10.2026 · **Материал:** DjVu-скан технической литературы (теплообменники,
гидродинамика), 10 страниц, 194 блока с текстом (разметка из `OCR_TEST.llocr`,
координаты блоков во всех проектах идентичны).

**Участники** (все распознавали одни и те же уже размеченные блоки):

| Модель | Проект |
| --- | --- |
| GLM-OCR | `OCR_TEST_GLM-ocr.llocr` |
| LFM2.5-VL | `OCR_TEST_LFM2.5-VL.llocr` |
| LightOnOCR-3 | `OCR_TEST_LightOnOCR-3.llocr` |
| MinerU2.5-Pro | `OCR_TEST_MinerU2.5-Pro.llocr` |
| PaddleOCR-VL-1.6 | `OCR_TEST_PaddleOCR-VL-1.6.llocr` |

TeleOCR не участвовал (нет поддержки кириллицы) — согласно условию теста.

## Методика

1. Эталон снят вручную с изображений страниц (200 dpi): каждый блок
   транскрибирован по своему кропу — включая строки-«огрызки», попадающие в
   кроп соседнего блока (например, «Теплопроводность λ» частично входит в блок
   «Число Прандтля» на стр. 4). Блок-картинка (рис. 8.7, стр. 2) из сравнения
   исключена (все модели оставили её пустой).
2. Метрика — посимвольная (CER, distance Левенштейна), взвешенная по длине
   эталона = «процент ошибочных символов». Перед сравнением нормализуются
   конвенции записи: `$$`/`\[`-обёртки, `\mathrm`/`\text`/`\overline`,
   `\frac{A}{B}`→`(A/B)`, `\ell`→`l`, `\tag{n}`→`(n)`, окружения `array/aligned`,
   юникод-греча, дефисы/переносы строк, кавычки, разрядка. Регистр
   **различается** (КАПС против строчных — ошибка).
3. Таблицы оценены двояко: (а) покрытие содержания — доля эталонных ячеек,
   найденных в выводе (нечёткое вхождение), (б) структура — размеры сетки,
   объединения ячеек, сохранность границ.
4. Блоки сгруппированы: простой английский текст (стр. 0), простой русский
   текст (стр. 1), русский текст с мат. вставками (стр. 2–5, 8–9), формулы
   (все `equation`-блоки), кириллица в формулах (стр. 3: индексы «н.впр»,
   «терм», «M_т» и т.п.), служебные (колонтитулы, номера страниц, подписи).

## Характерные ошибки по моделям

### GLM-OCR
- **Латинизация кириллицы внутри math-режима**: «терм» → `\mathrm{TepM}`,
  «н.впр» → `\mathrm{H.B} \pi \mathrm{p}` (п → π!), «Теплопроводность» →
  «Tenloprovodnost». Главная причина проигрыша на кириллических индексах.
- **Деградация на длинных русских абзацах**: «теплообменник» → «теплобменник»,
  «теплоноситель» → «теплосистель», «Даже» → «Далее», в конце стр. 1 —
  связный по стилю, но бессмысленный текст («а подтверждая, то воздействие
  неосредственно контактировать»). Ошибки «по нарастающей» к концу блока.
- КАПС-флип в мелких блоках: «Плотность ρ» → «ПЛОТНОСТЬ ρ».
- «103» → «1.03»; «Таблица 3» → «Табриya 3».
- В таблицах: десятичная запятая → точка (1,53 → 153/1.53) — для чисел это
  меняет значение.
- Уникальный плюс: rowspan/colspan в HTML-таблицах.

### LFM2.5-VL
- **Leetspeak/латиница на мелких кропах**: «Разд. 1.1» → «P3A4. 1.1»,
  «Таблица 3» → «Ta6nya 3».
- **CAPS-флип целых блоков**: обрезанный абзац вверху стр. 1 распознан
  целиком КАПСОМ (CER 97 % при верном тексте), заголовки — наоборот, строчными
  («§ 2.3.1. Введение…» вместо КАПСА). «Физические константы» → КАПС.
- «103» → «1.03» (как у GLM).
- Формулы: «ρ w n dS» → «\textnormal{and} S» (прочитал «wnd» как «and»),
  «k» → «\hbar».
- Ломает `<fcel>`-разметку таблиц (закрывающие теги без открывающих) — клетки
  сливаются, структура теряется при верном содержании.
- Плюсы: лучший контент таблиц (96 %), сохраняет десятичные запятые, en-текст
  идеален.

### LightOnOCR-3
- **На маленьких/одиночных кропах выдаёт описание картинки вместо текста**:
  для номера страницы «353» — «### Figure – Pixelated Symbols … *Type: other*
  The image displays three pixelated symbols…». 6 блоков пустых, служебные
  блоки провалены (75,6 %). В блочном режиме (blockRecognition) это опасно.
- **Обрыв больших формул на середине** (стр. 5, формула 65 закончилась на
  «+ \right.») либо обрамление формулы англоязычным «The equation is: …».
- Теряет номера формул: «S = ηW, (7)» → «S = \eta W,».
- Markdown-мусор вокруг таблиц, украинизмы («напряження»).
- Плюсы: лучший/второй русский текст (0,8 %), **лучшая сохранность кириллицы
  в формулах** (9,6 % — пишет «н.впр» кириллицей), чистый LaTeX, когда не
  обрывается.

### MinerU2.5-Pro
- Самая стабильная: единственный провал на весь корпус — одно-символьный блок
  «и», распознанный как «И» (регистр).
- **Подмена кириллицы/гречи на латинских двойников**: н → H, в → B, р → p,
  м → m, с → c, ν → v («моль/(м³·с)» → «моль/(m^3·c)»), R̄ → R̃. На стр. 3
  это даёт 18 % вместо ~5 %.
- Изредка мусорные `\left| … \middle/ …` вокруг формулы.
- Плюсы: лучший результат по формулам (4,7 %) и по суммарному качеству
  (2,1 %), лучшие сложные таблицы, аккуратные `\[…\]`-блоки.

### PaddleOCR-VL-1.6
- **Латинизация/leet в math-режиме**: «Число Прандтля» → «4uclo Ppandtlra»
  (Ч → 4), «Разд.» → «Pa3π.» (д → π).
- **Структурные поломки сложных формул**: лишние `\left|…\right|`, дробь
  «−B̄∫dτ/(1+…)» пересобрана в «\frac{\bar\tau}{B\int…}» (стр. 3, ф. 2.68 —
  CER 41 % даже после нормализации записей), `\eqno(8.37)` вместо `(8.37)`.
- **Схлопывание строк у бесформенных таблиц** (стр. 9): все строки величин
  склеены в одну ячейку, часть единиц измерения потеряна.
- Пустые микроблоки: «и», «где» (×3).
- Плюсы: идеальные простые формулы (стр. 2), хороший русский текст (1,1 %).

## Выводы

- **Универсальный лидер — MinerU2.5-Pro**: лучшая сумма (2,1 %), лучшие
  формулы, лучшие сложные таблицы, стабильность без провальных блоков.
  Её единственная системная слабость — подмена кириллических букв латинскими
  двойниками в формулах.
- **LightOnOCR-3** — лучший на русском тексте и на кириллице в формулах, но
  в блочном режиме требует защиты: не скармливать микро-кропы (слова из 1–3
  букв, номера страниц) и ждать обрывов на очень длинных формулах.
- **GLM-OCR и PaddleOCR-VL-1.6** системно латинизируют кириллицу внутри
  math-режима — для русскоязычных технических сканов это самый вредный класс
  ошибок (испорченные формулы не чинятся автоматикой и не находятся
  спелл-чекером).
- **LFM2.5-VL** в этом тесте не показал преимуществ: средние формулы,
  CAPS-флипы и leetspeak на мелких блоках, поломанная табличная разметка
  при хорошем содержании.

*Методика и скрипты: `_extracted/gt.py` (эталон), `_extracted/compare.py`
(метрики), `_extracted/render/`, `_extracted/crops/` (кропы и оверлеи).*
