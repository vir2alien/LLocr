# Материалы блочного OCR-теста (OCR_TEST)

Самодостаточный комплект для повторных прогонов и сравнения OCR-моделей.
Материал: DjVu-скан технической литературы, 10 страниц, 195 размеченных блоков
(разметка из `OCR_TEST.llocr`; во всех проектах координаты блоков идентичны).
Эталонный текст каждого блока снят вручную с изображений (не с вывода моделей).

Дата baseline: **2026-10-17**. Отчёт по прогону: `../REPORT.md`.

## Состав

| Путь | Что это |
| --- | --- |
| `gt.json` | **Главный файл**: разметка + эталон одним документом. На каждой странице — исходник, рендер, размеры; у каждого блока — label, координаты (0..1), категория (`group`), путь к кропу и эталонный текст `gt_text` (формулы — канонический LaTeX; у image-блока `null`) |
| `gt.py` | Эталон в виде python-словаря `GT[страница][блок]` (используется `compare.py`) |
| `compare.py` | Скрипт метрик: CER по блокам/категориям, парсинг таблиц. Запуск: `python compare.py` из этой папки |
| `projects/` | Распакованные `.llocr` всех участников + базовый `OCR_TEST` (вход `compare.py`) |
| `renders/` | Страницы-исходники в 200 dpi (PNG) — по ним снимался эталон |
| `overlays/` | Те же страницы с пронумерованными рамками блоков (навигация по разметке) |
| `box_crops/` | Индивидуальный кроп каждого блока (`pNN_bNN_label.png`, паддинг 4 px) — то, что «видит» модель при blockRecognition |
| `gt_notes/` | Контактные листы и увеличенные фрагменты, которыми пользовались при съёмке эталона (в т.ч. зумы спорных мест) |
| `results/summary.json` | Агрегированные метрики baseline (взвешенный и средний CER по категориям) |
| `results/baseline_boxes.json` | По-блочный CER всех пяти моделей (194 блока × 5) — база для сравнения будущих прогонов |
| `results/baseline_summary.json` | Снимок агрегатов от 17.10.2026 (дубликат на случай перезаписи `summary.json`) |
| `auxdata/` | Вспомогательное: `box_lines.json` / `line_assign.json` (детекция строк для сверки границ блоков), `boxes_layout.txt` (дамп координат). Имя `auxdata`, а не `aux`: `aux` — зарезервированное имя Windows, git не может читать такие файлы |

## Как добавить новую модель и сравнить с baseline

1. В LLocr распознать те же размеченные блоки новой моделью → сохранить
   проект `OCR_TEST_<модель>.llocr`.
2. Распаковать в `projects/OCR_TEST_<модель>/` (это ZIP):
   `unzip OCR_TEST_<модель>.llocr -d projects/OCR_TEST_<модель>`
3. Добавить путь в `MODELS` в `compare.py`.
4. `python compare.py` — сравнение со свежим эталоном; метрики новой модели
   сопоставлять с `results/baseline_summary.json` и `results/baseline_boxes.json`.
   Таблицы требуют deps: `pip install pymupdf pillow rapidfuzz` (рендер нужен
   только для новых кропов, для скоринга — `rapidfuzz`).

## Методика (кратко)

- Метрика — посимвольный CER (Левенштейн), взвешенный по длине эталона;
  «% ошибок» в отчёте = CER × 100. Регистр значим (КАПС против строчных —
  ошибка).
- Перед сравнением нормализуются конвенции записи: `$$`/`\[`/`$`-обёртки,
  `\mathrm`/`\text`/`\overline`/`\bar`, `\frac{A}{B}` → `(A/B)`, `\ell` → `l`,
  `\tag{n}` → `(n)`, окружения `array`/`aligned`, юникод-греча, дефисы и
  переносы строк, кавычки, разрядка. Полное описание — `norm_eq`/`norm_text`
  в `compare.py`.
- Эталон соответствует **содержимому кропа**: если в прямоугольник блока
  попадает «огрызок» соседней строки (например, «Теплопроводность λ» в кропе
  блока «Число Прандтля», стр. 4), он включён в эталон этого блока.
- Блок-картинка (рис. 8.7, стр. 2, `p2_b14`) из сравнения исключена — все
  модели оставили её пустой.
- Категории блоков: `en_text` (стр. 0), `ru_text` (стр. 1), `ru_math_text`
  (текст с формулами, стр. 2–5, 8–9), `equation` (формульные блоки),
  `table`, `service` (колонтитулы, номера страниц, подписи, сноски).
- Таблицы: покрытие содержания — доля эталонных ячеек, найденных в выводе
  (нечёткое вхождение, `fuzz.partial_ratio ≥ 0.85`); структура — размеры
  сетки, сохранность границ ячеек, объединения. Ячейки эталона в `gt_text`
  блоков `table` закодированы как `TABLE:ячейка|ячейка;;строка;;строка`,
  маркер «(объед. …)» в эталонной ячейке означает объединение, при скоринге
  содержания он отрезается.

## Замечания по воспроизводимости

- Числа `compare.py` полностью воспроизводят отчёт (`../REPORT.md`) на дату
  2026-10-17 (проверено перезапуском из этой папки).
- Нормализация честна ко всем моделям, но не идеальна: часть расхождений
  форматирования (`\left\right`, стиль дробей, вложенные индексы) сознательно
  не штрафуется; регистр и кириллица/латиница штрафуются всегда — это часть
  задания (русские символы в формулах).
