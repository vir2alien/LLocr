# Проба: «распознать с нуля» против «исправить ранее распознанное» — qwen3.5-4b

Модель: **qwen3.5-4b** (Qwen3.5-4B, MTP, Q8_0), MTP-драфтер внутри самого GGUF
(`--spec-type draft-mtp`, отдельный файл не нужен).
Рантайм: llama.cpp b11799 на **CPU** (`--device none --n-gpu-layers 0`) — Metal в
песочнице недоступен.

Корпус, обе руки, промпты и метрики — те же, что в `results/probe_gemma4e4b/REPORT.md`
(корпус `corpus/corpus_probe5.json`, 5 формул; рука **fix** — запрос из профиля
`fix-requests.json` через порт гейта; рука **read** — запрос на распознавание из
`probe.py`; обе руки получают одинаковое знание об осях проверки).

**Теория на этой модели не подтверждается — наоборот.** Рука read (0.187) хуже и
кандидата (0.154), и фикса (0.142).

## Сколько из этого — LaTeX-мусор, а сколько — непрочитанное

qwen в режиме распознавания печатает формулу в «датасетном» стиле: пробел между каждым
токеном, `\nonumber` перед разрывами строк, `\displaystyle`. Нормализация сравнения
(`compare.norm_eq`) пробелы снимает, а `\nonumber` и `\\` — нет, и они становятся
символами, которых нет в эталоне.

После снятия только этого мусора (`\nonumber`, `\displaystyle`, `\\`):

```
uid        CER read сырой  CER read чист
p03b03                  0.256            0.256
p03b05                  0.091            0.091
p03b12                  0.190            0.190
p03b14                  0.250            0.250
p05b09                  0.149            0.021
СРЕДНЕЕ                 0.187            0.161
```

Весь разрыв на p05b09 — это `\nonumber`/разрывы строк, не непрочитанное: после снятия
мусора рука read даёт 0.021 против 0.033 у фикса. Но и без этого мусора read (0.161)
остаётся хуже фикса (0.142). Вывод не меняется, просто он не такой драматичный.

## Что показала каждая рука

| блок    | fix                                        | read                                                       |
| ------- | ------------------------------------------ | ---------------------------------------------------------- |
| p03b03  | `H.Bnp` сохранён, `M_Π` сохранён            | `H.BIpp` — хуже кандидата; индексы 0.22 против 0.33 у кандидата |
| p03b05  | `T_{Нвпр}` → `T_{нвпр}` (починил)          | **кириллица верно**: `Q_{\text{тeрм}}`, `M_{\text{т}}`, `R_{\text{в}}`, `T_{\text{нвпр}}`, `Q_{\text{исп.впр}}` — индексы 0.82, лучше всех рук |
| p03b12  | `H.BPp` сохранён (вердикт `Ok`)             | `H.BIpp` / `H.BInp` — хуже кандидата; тег `2.696` та же ошибка |
| p03b14  | `H.Bnp` сохранён                            | `H.BIpp` — хуже кандидата; тег `2.70a` та же ошибка          |
| p05b09  | `v_r` → `V_r` поправил, структуру сохранил  | структуру сохранил, `V_r` не поправил, но наследил `\nonumber` |

Ключевое: **рука fix по-прежнему переписывает блок по кандидату** — `H.Bnp`, `M_Π`,
`H.BPp` остаются как были. Но у qwen фикс кое-что всё же чинит (p03b05: `T_{Нвпр}` →
`T_{нвпр}`, CER 0.097 → 0.056), и на этом его средний результат лучше геммыного (0.142
против 0.153).

Рука read у qwen **нестабильна по скрипту**: в p03b05 кириллица прочитана верно (0.82
индексов — лучший результат среди всех рук и моделей), а в p03b03/p03b12/p03b14 та же
подстрочная надпись прочитана как `H.BIpp` — хуже, чем её прочитал OCR-движок, создавший
кандидата.

## Сводка по двум моделям

```
                 кандидат      fix     read (сырой)   read (без мусора)   инд: канд/fix/read
gemma-4-e4b        0.154     0.153        0.069            0.066          0.52 / 0.54 / 0.87
qwen3.5-4b         0.154     0.142        0.187            0.161          0.52 / 0.58 / 0.57
```

* **gemma-4-e4b** — теория подтверждается резко: чтение с нуля в 2.2 раза ближе к эталону,
  индексы 0.87 против 0.54 у фикса.
* **qwen3.5-4b** — теория не подтверждается: чтение с нуля хуже и кандидата, и фикса.

Разница не в размере (обе ~4B) и не в железе (один и тот же CPU, один и тот же рантайм).
Разница, судя по всему, в том, как модель «по умолчанию» относится к картинке: qwen
воспроизводит стиль OCR-датасета (пробелы, `\mathrm`, транслитерация мелкой кириллицы в
латиницу), gemma читает как внимательный человек. Это гипотеза, а не установленный факт:
чтобы её проверить, нужен прогон с разными промптами распознавания на одной модели.

## Время (CPU)

47.6 с на запрос fix, 47.2 с на запрос read — вдвое быстрее gemma-4-e4b (105.7 / 117.9)
при том же кванте Q8_0 против Q4_K_XL и другой реализации внимания.

## Воспроизведение

```sh
cd OCRtest/fix_models
python3 probe.py --model qwen3.5-4b --config configs/qwen3.5-4b-cpu.json \
    --corpus corpus/corpus_probe5.json --out results/probe_qwen35_4b \
    --server-override device=none
```

Сервер поднимает и останавливает сам `probe.py` (в отличие от гемминого прогона, где
сервер был поднят вручную и остался жить на `:8128`).
