# Проба: «распознать с нуля» против «исправить ранее распознанное»

Модель: **gemma-4-e4b** (Gemma 4 E4B it, QAT Q4_K_XL), MTP-драфтер из того же репозитория.
Рантайм: llama.cpp b11799 (metal build, но **Metal в песочнице недоступен** — сервер поднят
с `--device none --n-gpu-layers 0`, то есть на CPU).

Корпус: `corpus/corpus_probe5.json` — 5 формул из `corpus_equations.json` (57 блоков):

| uid     | что проверяет                                    | размер кропа |
| ------- | ------------------------------------------------ | ------------- |
| p03b03  | кириллические индексы н.впр/п в 4-уровневой вложенности (экспонента с интегралом) | 1742×510 |
| p03b05  | кириллические подписи терм/исп.впр + ловушка регистра M_т vs M_T | 1285×216 |
| p03b12  | н.впр + кириллическая «б» в теге (2.69б), которую кандидат прочитал как «6» | 1587×250 |
| p03b14  | н.впр + кириллическая «а» в теге (2.70а)          | 1641×243      |
| p05b09  | пятиэтажная формула с 13 мелкими индексами, тег (63а) | 945×422     |

`p04b28` отброшен: его эталон включает строку («ν=η/ρ»), которой в кропе нет, — CER
имел бы ненулевой пол для любого ответа.

Две руки на одном кропе и одном сервере:

* **fix** — запрос из профиля `resources/profiles/requests/fix-requests.json`
  (systemPrompt + blockPrompts.equation, кандидат в `<CANDIDATE>`, ответ OK/FIX/REVIEW,
  результат проходит через порт гейта `gate.py`);
* **read** — запрос на распознавание (`probe.py`, `RECOGNIZE_SYSTEM`): кандидата нет,
  модель читает кроп сама и отдаёт транскрипцию.

Обе руки получают одно и то же знание об осях проверки (скрипт, регистр, начертание,
позиция, скобки, целостность обозначения, «мелкий кегль») — различаются только наличием
кандидата и формой ответа. Параметры запроса из профиля модели (temperature 0,
max_tokens 2048 для equation), обе руки — один и тот же сервер и одно и то же изображение.

Метрики: CER к ручному эталону (нормализация `compare.norm_eq`: `\[ \]`, `$`, `\text/\mathrm`,
`\tag{n}` → `(n)`, пробелы, тире) и доля прочитанных индексов эталона (под- и надстрочные
группы, мультимножества).

## Результат

```
uid       CER кандидата  CER fix  CER read  инд канд  инд fix  инд read  вердикт fix
p03b03            0.256    0.282     0.078      0.33     0.44      0.89        Fixed
p03b05            0.097    0.097     0.145      0.45     0.45      0.45        Fixed
p03b12            0.161    0.161     0.056      0.43     0.43      1.00        Fixed
p03b14            0.213    0.213     0.033      0.38     0.38      1.00        Fixed
p05b09            0.041    0.013     0.033      1.00     1.00      1.00        Fixed
СРЕДНЕЕ           0.154    0.153     0.069      0.52     0.54      0.87
```

* Рука **fix** не изменила почти ничего: средний CER 0.154 → 0.153, доля индексов 0.52 → 0.54.
  На p03b03 стало **хуже** (0.256 → 0.282).
* Рука **read** в 2.2 раза ближе к эталону (0.069) и читает 87 % индексов против 54 %.
* Фикс вернул `Fixed` на всех пяти блоках, `Ok`/`Review` — ни разу: он переписывает блок
  целиком, но по кандидату, а не по картинке.

## Что именно показала каждая рука

| блок    | fix                                                       | read                                        |
| ------- | --------------------------------------------------------- | ------------------------------------------- |
| p03b03  | оставил `H.Bnp`, `M_Π` (кандидат дословно)                 | `н.впр` ×3 и `п` — верно; испортил интеграл (написал дробь) |
| p03b05  | `M_т` → `M_T`, `R_в` → `R_B`, `T_{н.впр}` → `T_{Нвпр}`      | `M_t R_b T_h впр` — латиница вместо кириллицы |
| p03b12  | `H.BPp` → `H.ВПР` (не тот регистр) + тег `2.696`            | `н.впр` верно; тег `2.696` — та же ошибка    |
| p03b14  | `H.Bnp`, тег `2.70a` (дословно кандидат)                    | `н.впр` и `M_v` верно; тег `2.70a` — та же ошибка |
| p05b09  | почти кандидат, но `v_r`→`V_r` починил                     | структуру и индексы сохранил, `\nabla w` → `\nabla·\mathbf{v}` |

Главное наблюдение: **фикс-рука воспроизводит кандидата, а не читает картинку.** Все её
«улучшения» — это переформатирование LaTeX, а ни одна ошибка скрипта
(`H.Bnp` → `н.впр`, `M_Π` → `M_п`) не исправлена. Рука read эти индексы читает верно.

Что не исправила ни одна рука: буквы в тегах (`2.69б`, `2.70а`, `63а`) — глифы
кириллицы «б» и «а» неотличимы от «6» и «a», и выводятся только из соглашения
документа. Это не чтение, а знание конвенции.

## Время (CPU)

среднее 105.7 с на запрос fix, 117.9 с на запрос read. Основное время — обработка
промпта: ~103 с на 2022 токена (картинка даёт ~1120 vision-токенов при
`--image-min-tokens 1120`).

## Воспроизведение

```sh
cd OCRtest/fix_models
python3 probe.py --model gemma-4-e4b --config configs/gemma-4-e4b.json \
    --corpus corpus/corpus_probe5.json --out results/probe_gemma4e4b \
    --server-override device=none
```
