# fix_models — стенд для улучшения fix-задачи (qwen3.5-4b)

Задача: `qwen3.5-4b` (Q8) не исправляет **индексы формул** — подстрочные
индексы вроде `н.впр`, `п`, `т`, `в`, `у` он читает как латиницу (`H.Bnp`,
`Π`, `T`, `B`, `v`) и в ответе повторяет ошибку кандидата. `gemma-4-12b`
справляется, `qwen3.5-9b` — почти. Запрос рабочий (большая модель его
выполняет), значит вопрос в том, как именно дать маленькой модели нужную
информацию.

Материалы и стенд — здесь; код приложения не требуется.

## Короткий вывод

| что | эффект |
| --- | --- |
| **режим мышления** (`--reasoning-budget 512` + `enable_thinking: true`) | главный выигрыш: индексы 0.54 → 0.65 на проблемной странице |
| **подсказка о скрипте** в системном промпте | +0.08 индексов; сама по себе почти безвредна, в паре с мышлением — решающая |
| **увеличение кропа в 2 раза** (бикубическая) | работает **только вместе** с мышлением (сам по себе — минус) |
| повтор промпта (arXiv 2512.14982) | не помогает (×2 хуже, ×3 — как мышление без подсказки) |
| бюджет vision-токенов (`--image-min-tokens`) | не помогает: картинка и так кодируется в полном разрешении |
| «прочитать самому и потом исправить» (два шага) | хуже: собственная транскрипция модели хуже кандидата |
| контекст страницы рядом с кропом | не помогает |

Итог на проблемной странице (7 блоков): **CER 0.140 → 0.062, индексы
0.54 → 0.78, 4 улучшено / 1 испорчено** — против 2 / 0 у приложения как есть.
На всех 57 формулах книги: CER 0.055 → 0.040, индексы 0.87 → 0.91, а на
блоках с ошибками — 11 улучшено против 1 испорченного (было 8 / 3).

Цена: ~37–55 с на блок вместо 12–18 с.

## Корпус

Страница 3 корпуса OCR_TEST (теплообменники, `4_eq_hard2.pdf`, формулы
2.68–2.70) — та самая страница из задания. Пять формул и два текста с
формулами:

| uid | тип | что не так в кандидате (MinerU2.5-Pro) |
| --- | --- | --- |
| `p03b02` | text | `M_{\pi}` вместо `M_п` |
| `p03b03` | equation | `н.впр` → `H.Bnp` (4 раза), `M_п` → `M_Π`, потерян `\bar` над `\tau`, мусорные `\left\| … \right.` |
| `p03b05` | equation | `M_т` → `M_T`, `R_в` → `R_B`, `н.впр` → `нвпр`/`Н.впр` |
| `p03b09` | text | мелочь (эталон почти совпадает) |
| `p03b11` | equation | `н.впр` → `H.Bnp` (2 раза) |
| `p03b12` | equation | `н.впр` → `H.BPp` (2 раза) |
| `p03b14` | equation | `н.впр` → `H.Bnp` (3 раза), `M_у` → `M_v` |

* **Кандидат** — реальный текст распознавания MinerU2.5-Pro из
  `OCRtest/decision_models/test 2/OCR_TEST_MinerU2.5-Pro.llocr` (не
  синтетика): ошибки настоящие.
* **Эталон** — ручная транскрипция `OCRtest/ocr_models/materials/gt.json`,
  выборочно сверена с кропами.
* **Кроп** — рендер исходной страницы в 300 dpi (`DocumentModel::kDpi`) и
  прямоугольник блока, ровно как `AppController::croppedImage`.

Другой корпус — один аргумент:

```sh
python3 corpus/build_corpus.py --groups equation --out corpus/corpus_equations.json
python3 corpus/build_corpus.py --blocks p03b03,p03b05 --out corpus/corpus_small.json
```

## Как приложение шлёт fix-запрос (что воспроизводит стенд)

`VerificationQueueController::startNextVerify` → `FixController::fixBlock` →
`FixModel::buildRequestBody`:

* кандидат = `FixDiffGate::normalizeLatexCandidate(текст блока)` — пробелы
  перед скобками убраны (`\frac {p}` → `\frac{p}`);
* сообщения: `system` (промпт профиля запросов, `{{LANGUAGE}}` → Russian) и
  `user` с тремя частями: typePrompt по типу блока → картинка кропа →
  `OCR candidate:\n<CANDIDATE>…</CANDIDATE>`;
* `chat_template_kwargs: {enable_thinking: false}`;
* параметры запроса из профиля модели: temperature 0, repeat_penalty 1.0,
  stop `[<|im_end|>, <|endoftext|>, </CANDIDATE>]`, `max_tokens` — из
  `maxOutputByBlock` (1024 для формул и текста);
* ответ: `OK` / `FIX` + правки / `REVIEW`. Формула отвечает **целиком**
  (ADR 181), гейт применяет её как исправление, если она не эквивалентна
  кандидату.

Стенд считает не ответ модели, а **результат гейта** (`gate.py` — порт
`FixDiffGate.cpp`): `Ok` / `Fixed` / `Review` и итоговый текст блока.

## Метрики

* **CER** (посимвольный, после нормализации `compare.py`) кандидата и
  исправленного текста против эталона; `улучш` / `порч` — знак разницы.
* **Индексы** — доля под- и надстрочных групп эталона, присутствующих в
  тексте (мультимножества, не подстроки). Это и есть «прочитал ли индекс».
* **Вердикты** — `Ok` / `Fixed` / `Review` от гейта.

## Прогон

```sh
cd OCRtest/fix_models
python3 corpus/build_corpus.py            # собрать корпус (если менялся)
python3 run.py --all                      # все варианты (сервер поднимается сам)
python3 run.py --variant v0_app --variant combo_hint_think_2x
python3 run.py --all --base-url http://127.0.0.1:8123   # сервер уже запущен
python3 report.py results/r1/rows.jsonl --subset errors
```

Ответы кешируются по хешу запроса (`results/cache`), прогон resumable:
повторный запуск не тратит время. `--refresh` — обойти кеш.

Сервер поднимается с аргументами приложения (`--spec-type draft-mtp`,
`--image-min-tokens 1024`, `--reasoning-budget 0`, `--ctx-size 16384`, …);
варианты, меняющие серверные параметры, группируются по ним — сервер
перезапускается между группами (порт проверяется: старый сервер должен
умереть, иначе запросы уйдут к нему и «параметр не влияет» получится
ложно — на этом споткнулся первый прогон).

## Что сработало и почему

1. **Мышление — единственное, что даёт разбор по осям.** Без него модель
   переписывает формулу «по памяти» и тащит из кандидата ошибку индекса.
   С мышлением (бюджет 512) в `reasoning_content` появляется разбор
   «Script / Case / Face / Position» — и в `p03b03` индексы
   `p_{\mathrm{H.Bnp}}` → `p_{\mathrm{н.впр}}` становятся кириллицей.
   Бюджет 2048 — хуже: ответ не влезает в `max_tokens` блока, все семь
   блоков уходят в Review.
2. **Подсказка о скрипте.** Диагностика `read_only` показала: в **тексте**
   модель читает кириллицу правильно (`M_{\text{п}}` — верно!), а в
   **формуле** переводит индексы в латиницу (`н.впр` → `H.BIpp`). То есть
   ей не хватает знания, что это кириллица, а не начертание. Слова
   «прочитай кириллицей, а не латинскими двойниками» хватает.
   Вариант «правилом» (правило сформулировано через `{{LANGUAGE}}`,
   примеры транслитерации даны) работает не хуже явного списка букв —
   значит, в приложении подсказку можно писать один раз для всех языков.
   Совсем обобщённая формулировка («индексы — буквы алфавита документа»)
   работает заметно слабее: примеры в тексте подсказки важны.
3. **Увеличение кропа в 2 раза** даёт эффект **только вместе** с мышлением:
   картинка становится вдвое крупнее по пикселям, и индекс `н.впр` (в
   исходнике ~15 px высотой) перестаёт быть одним vision-токеном. Само по
   себе увеличение не помогает и даже чуть вредит — модель без разбора
   просто переписывает формулу.
4. **Бюджет vision-токенов нерелевантен.** `--image-min-tokens 4096`
   действительно поднимает число токенов картинки (2198 → 5283), но ответ
   не меняется: картинка и так кодируется в полном разрешении исходника,
   а лишние токены уходят в увеличение пустых полей. Потолок
   `--image-min-tokens 8192` упёрся в `image_max_pixels` mmproj и сервер
   не стартует (`image_max_pixels (4194304) is less than image_min_pixels
   (8388608)`).
5. **Повтор промпта (arXiv 2512.14982) не помогает.** ×2 — как базовая
   линия (CER 0.148, индексы 0.50), ×3 — на уровне мышления без
   подсказки, но дороже. Модель повторяет не чтение, а кандидат: если
   ошибка индекса есть в кандидате, она есть и во втором повторе.
6. **«Сначала прочитать, потом править» хуже.** Собственная транскрипция
   модели (`read_only`) хуже кандидата: на тексте с формулой она
   выдаёт мусор (`TenJ o ,П О В В О А А Н О е \ К Т О Н Ж I B y y`), на
   формулах — латиницу. Опораться ей не на что.
7. **Контекст страницы рядом с кропом** ничего не даёт: модель не
   «выводит» алфавит документа из соседнего текста.

## Как это переносится в приложение

Три правки, все в профилях и в одном месте кода:

1. **Мышление** — `resources/profiles/models/qwen3.5-4b.json`, роль `fix`:
   `reasoning-budget` 0 → 512. Плюс `enable_thinking: true`: сейчас
   `VisionChatModel::buildRoot` жёстко шлёт `chat_template_kwargs:
   {enable_thinking: false}` — нужен переключатель (например, поле в роли
   профиля модели, чтобы «мышление» включалось вместе с бюджетом).
   **Разбор ответа править не нужно:** llama.cpp кладёт мысль в
   `message.reasoning_content`, а `FixModel` читает только `content` —
   вердикт приходит чистым.
2. **Подсказка о скрипте** — `resources/profiles/requests/fix-requests.json`,
   абзац в системном промпте (текст блоков «скрипт» уже есть — туда и
   дописать). Формулировка «правилом» (с `{{LANGUAGE}}` и примерами
   транслитерации) обобщается на любой язык.
3. **Увеличение кропа** — код: `AppController::croppedImage` отдаёт сырой
   кроп; для fix-задачи нужен масштаб 2 (бикубический). Это настройка
   задачи (профиль/опция), а не общий дефолт превью.

Ожидаемый эффект в приложении: на проблемной странице индексы исправляются
в 2.2 раза чаще (0.54 → 0.78), на книге — CER 0.055 → 0.040, а число
испорченных блоков падает (3 → 1 на ошибочных). Цена — время: ~40–55 с на
блок вместо 12–18 с (мышление + картинка вдвое крупнее).

## Ограничения

* Малый корпус — 7 блоков; большие числа на нём (±1 блок) ничего не
  значат. Выводы «мышление и подсказка работают» подтверждены на 57
  формулах, но и там блоков с ошибками всего 28.
* Один квант (Q8), одна модель, один OCR-кандидат (MinerU2.5-Pro).
  Другие OCR-ошибки (латиница ↔ кириллица в тексте) в корпусе почти не
  представлены.
* Эталон `gt.json` местами неверен (например, `p03b13`: «Приближенно приar{B}ar{B}_1»);
  такие блоки в корпус не брались, но в других прогонах появятся — правки
  эталона живут в `corpus/overrides.json`.
* Метрика CER к эталону считает и различия записи (`\mathrm{н.впр}` против
  `н.впр`), поэтому абсолютные значения занижены; для сравнения вариантов
  это неважно (эталон один и тот же).
* Все ответы — greedy (temperature 0) и детерминированные; повторный
  прогон воспроизводится из кеша побайтово.
